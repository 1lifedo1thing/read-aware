# ReadAware 能力交付

本仓库能力工作的执行入口。用户当前要求决定范围和阶段；历史账本、旧 goal、
记忆中的闭合流程与本文不一致时，不沿用旧执行步骤。事实和有效证据仍保留。

## 接续与范围

- 从当前请求、工作区增量和已有交接恢复任务，只读受影响的矩阵行、实现与证据。
  矩阵数据源是 `docs/host-capability-matrix.data.ts`，模型是
  `docs/host-capability-model.data.ts`；账本和第三段清单均按行 ID 查找，
  不因新回合或上下文压缩从头重做全量审计。
- 长任务在 `docs/host-capability-delivery.md` 顶部维护一条简短交接：当前范围与
  阶段、具体剩余调用断点、已通过检查及其对应改动、下一步实施动作。新记录替换
  这条交接，详细证据放历史记录。压缩后先恢复它，不重新回答已经处理的旧问题。
- 用户要求全部补齐时，保持全部约定范围；按共享领域成批只是实施顺序，完成一批
  不能结束整项任务。goal 的创建、修改和结束遵循工具规则，不自动创建后续 goal。
- 对当前批次明确“谁能完成什么操作、还缺哪段调用链、怎样判定接通”。优先使用
  已有关闭条件；只有原条件含混时才补充，不另起一轮架构设计。
- 新发现的问题只在阻塞约定行为或有具体正确性、安全失败证据时加入当前前置工作，
  写明对应断点。其他需求、加固与额外平台验收单列；用户明确要求的项目不能降为后续。

## 接通与验收分开判断

| 事实 | 推进方式 |
| --- | --- |
| 缺宿主实现或公共入口 | 接宿主、公共契约、Agent 工具与插件运行时的实际调用链 |
| 入口存在，但权限、写入结果或必要业务语义不正确 | 修实际断点，不能用声明、空实现或假成功计作接通 |
| 调用链及相关检查通过，尚缺指定运行环境的证据 | 记录待验收；接线阶段继续剩余调用链，验收阶段再运行对应场景 |
| 自动行为、特定 actor 不适用、设计不开放或新增产品功能 | 按已约定语义分别记录，不以消灭“未接”标签为由开放原始权力或增加产品范围 |

矩阵“部分”是调查入口，不是可直接求和的工作量。分别报告实现缺口与验收缺口；
只有实现或证据支持时才修改状态。未知边界不能抹去，已经跑通的行为也不反复归零。

## 实施与检查

- 以可调用的完整能力为交付单位，共用现有 domain、Agent port 与 Worker 接线。
  内部模块可以分次提交，但下一步优先补完这条链，内部提交不算能力完成。
- 前置工程连续增加而当前调用断点仍未减少时，重新检查依赖是否必要，调整实现路径；
  不靠增加测试、文档或再次盘点维持“有进展”，也不因此擅自停掉剩余授权工作。
- 接线阶段只做受影响的类型检查、必要的正确性/权限/持久写/取消与资源释放回归。
  检查通过后复用证据；相关改动、失败或明确未解决的问题才触发重跑或扩大检查。
- 用户指定集中验收时，接线阶段不逐行启动 Tauri 或要求正式插件轮次通过。
  到验收阶段按有意义的组合流程测试，在用户指定的真实环境观察结果；
  `docs/host-capability-stage-three.md` 提供候选用例，不自动增加本次平台或故障范围。
  用户要求当前能力同时验收时，就在本次完成，不能以默认分阶段推迟。
- 文档随连贯批次同步事实和生成结果；内容修改不触发未变化模板的视觉回归。
  按已有授权提交、推送；无关 CI 不阻塞下一步实现，相关 CI 失败须处理。

## 交付与停止

报告本批哪些操作已能执行、还有哪些具体断点、实际验证边界。提交数、断言数和
内部入口数只作支持。批次通过后继续当前范围的下一批；全部约定条件满足才结束。
外部阻塞按真实状态处理，不用重复检查代替推进。新任务不自动继承已结束 goal 的待办。

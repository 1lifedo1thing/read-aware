# 阅读访谈建档

`onboard_reader` 是全局 Agent 的可选访谈工具，不是第二个 Agent。模型只提供本地化标题和四个问题标签，不能预填答案。宿主表单收集目标、背景、解释深度与语言；空答、跳过和拒绝均不写入。用户随后看到完整画像和每条事实/偏好记忆，明确批准后才保存。已有非空画像不由该工具覆盖，纠正仍走 `update_user_profile`。是否提出访谈由当前对话决定，不强制打断阅读。

## 一次提交

公共契约位于 core 的 `OnboardingChange`。画像最多16000 UTF-16，最多4条种子，每条最多4000 UTF-16，类型只有 fact/preference；不接受权重、身份、scope 或事件字段。输入在异步工作前复制。`memory 2.5 commands.completeOnboarding` 需要 memory:write，插件仍必须提供自己的完整候选确认界面；写权不是宿主批准票据。两端均受宿主 buildMemory 开关限制。调用者在派发前取消不写；派发之后等待真实事务结果，不假装回滚。

原生 `onboarding_commit` 在一个 IMMEDIATE 事务内验证 profile2 版本、本机事件身份和 HLC，然后提交一个 `profile.onboarded`。apply 层以此事件同时投影画像、确定性 ID 的 user scope 种子和 `onboarding_receipts`。日志、outbox、所有投影和回执一起提交，任一插入失败全部回滚；不再存在画像成功但种子只保存一半的中间状态。

## 重试和同步

submissionId 是调用者作用域内1至64位 ASCII 字母、数字、下划线或连字符。回执按 origin + submissionId 隔离，绑定完整候选及所见版本的哈希。相同 ID/相同候选返回原 memoryIds/revision 和 already-completed，不再写事件；不同候选复用 ID 返回 memory/conflict。冲突必须重新读取、重新确认并使用新 ID，不能盲重试。

回执确认的是原提交，不证明画像或种子现在仍未被编辑/遗忘，也不会复活这些对象。回执是 schema38 的事件投影，参加重放、检查点、漂移验证及清空；genesis 识别复合事件生成的种子，不另造创建事件。跨设备同一 owner/ID 由完整 HLC 顺序的首条事件胜出；离线 CAS 不是分布式锁。旧客户端需升级才能投影此新事件；迁移遇到此前未知事件或未完成回填会要求完整重放，不乱序覆盖后来画像。

表单草稿和尚未批准的访谈不自动保存为长久任务。应用关闭前未提交的访谈可重新开始；已提交但回执丢失的调用可以用保留的 ID/完整候选重试。此命令不合并已有相似记忆、不替代日常巩固、不保证远端同步或模型语义质量。

## 验证

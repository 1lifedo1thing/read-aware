# 插件传输总预算

单消息形状/字节验证之外，宿主对全部 Worker 使用同一个资源池和双向流量桶。额度不接受插件传入的 owner、计数或释放数；同 ID 更新候选与旧实例各自持有真实租约，共享总限额。

## 存活资源

| 资源 | 单实例既有上限 | 全 App 上限 |
| --- | --- | --- |
| 进入宿主的在途 RPC | 256 | 1024 |
| 等待 Worker 回调的 RPC | 256 | 1024 |
| 注册与在途注册预留 | 4096 | 16384 |
| 解码后持有的回调 | 200000 | 500000 |

每个进入宿主的调用先预留 RPC 与注册额度，之后才解析方法并执行业务。满额稳定返回 plugin/busy，不能先替换贡献再发现超限。普通结果释放预留；返回 disposable 时租约转移给真实注册，注销/退休清理释放。回调按已解码图中的唯一 handle 租约计数，单个回调释放和整实例退出均幂等，不能靠重复释放、复用 handle 或替换实例降低其他持有者的计数。

进入宿主的 RPC 等处理承诺实际结束才释放；向 Worker 的调用在结果、超时或实例终止时释放等待项。已派发持久写仍走既有生命周期排空，不因超限假装回滚。原生源读取/异步资源有各自的清理生命周期，这个表不是其内存计数。

## 消息流量

| 维度 | 每实例突发 / 每秒恢复 | 全 App 突发 / 每秒恢复 |
| --- | --- | --- |
| envelope 数 | 16384 / 4096 | 65536 / 16384 |
| 核算字节 | 256 MiB / 64 MiB | 512 MiB / 128 MiB |
| 图访问项数 | 4000000 / 1000000 | 16000000 / 4000000 |

两方向共用额度，含启动、控制、取消、结果、同步、释放和非法消息。先计 envelope 再遍历数据图；图按原单消息算法核算，失败时也结算已经访问的字节和项数，不让超大或非法请求成为免费路径。时间使用单调时钟，恢复不超过突发上限；不退还流量，实例重启不能清空全 App 的桶。

累计流量耗尽时退休触发超限的实例，取消等待、移除贡献并排空已接受工作，不继续为洪泛逐条生成拒绝回包。不能丢弃同步消息却让插件继续使用旧镜像。未触及累计限额的普通单消息错误仍沿用原有稳定拒绝与恢复语义。全 App 桶不预留每插件份额，繁忙时其他实例也可能在下一次发送/接收时触及总上限，不能宣称公平带宽保证。

这是宿主消息准入和存活句柄上限，不是 WebView/OS 队列、structured-clone 峰值内存、插件自身 CPU/堆内存或全部业务对象的硬限制。原生网络累计额度、完整业务压力与跨平台打包验收分别保留在 SYS07/CON04 中，不能由此自动关闭。

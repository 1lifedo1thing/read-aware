# 本地 API 与 Agent Skill

ReadAware 提供本机只读 HTTP API，让其他 AI 使用自己的 HTTP 工具读取当前阅读数据。
入口是 **Settings → AI → Local API**；默认关闭，开启后需要保持桌面应用运行。
正式版监听 `127.0.0.1:19280`，DEV 版监听 `127.0.0.1:19281`，端口占用时明确报错。

在设置里保存或复制 [ReadAware Skill](../../apps/web/src/assets/skills/readaware/SKILL.md)，
将其放到外部 AI 的 `readaware/SKILL.md`，再单独配置“复制连接配置”得到的地址和访问令牌。
Skill 是随应用发布的唯一接口使用说明，不包含凭据，不依赖 MCP。
远程 AI 的执行环境必须能在这台电脑上发送请求；云端的 localhost 无法直接访问本机。

当前开放书库元数据、目录、分段正文、正文搜索、批注、阅读记录和显式 scope 的记忆分页。
响应使用已有 domain 的公开读模型，不开放配置、密钥、原始文件、SQL、任意 IPC 或写操作。
跨书搜索仅覆盖已有的本地文本索引；指定书籍的搜索及正文读取可按需准备衍生文本。
正文接口可能读到尚未阅读的章节，Skill 指示外部 AI 根据用户问题和阅读位置控制范围。
上下文包继续承担可携带的版本快照用途；实时查询使用本地 API。

## 运行边界

- Rust HTTP 层只监听 IPv4 loopback，验证 Host 和 Bearer token，拒绝浏览器 Origin 和非 GET 方法。
- 访问令牌独立于模型及同步凭据，存入现有加密 secret store，不进入同步 credential family。
- 主窗口启动后登记请求接收器，显式路由表调用已有只读 domain 接口；没有第二套数据库查询。
- 最多 8 个并发请求、30 秒等待、2 MiB JSON 响应。查询限额及分页方式详见 Skill。
- 关闭停止监听；重置令牌使旧令牌失效。页面重新加载会撤销上一轮未完成请求；读取错误返回非 2xx，原始错误仅进入应用日志。
- 其他语言暂时回退英文设置文案；已提供简体中文。

## 已验证边界

2026-09-19 在运行中的 macOS Tauri DEV 应用，通过真实 loopback HTTP 读取了 43 本书的书库、
《肖申克的救赎》的目录及正文、正文搜索、批注、进度和已有记忆。首次这组读取约 4–38 ms，
这是本机已有数据的样本，不代表首次文本提取耗时或跨设备性能保证。
验证了缺少/错误令牌、外部 Host、浏览器 Origin、写请求、凭据路由和非法参数均被拒绝。
另验证了应用重启保留连接、令牌重置拒绝旧连接、关闭服务停止监听、端口占用明确失败，
以及设置内复制连接和复制 Skill。此记录不代表 Windows/Linux 或打包发布版本验收。

# 完整备份实现边界

OPS08 完整加密备份与合并恢复已接通，并通过隔离 macOS Tauri 的代表性成功与失败验收。用户可在设置中选择完整归档或旧 v1 书库子集；完整恢复提供口令、认证预检、差异选择、程序授权、执行结果与重载。[桌面验收记录](./acceptance/ops08-backup-2026-09-12.md)与[交付账本](./host-capability-delivery.md)保留证据和未验证边界。

## 数据覆盖与保留规则

完整归档使用内部 format2，age 口令认证加密，包含同一SQLite读事务的实际数据库副本、事件与历史投影、书籍及全部登记未删除blob、批注、书单、独立聊天及呈现状态、记忆、普通设置、插件程序/KV/文档/schema，以及恢复凭据所需的密封值和来源key。旧数据中未记录在事件中的实际状态不会被一次重放丢弃。FTS和其他可重建投影保留结构并沿既有恢复路径处理。

归档里的本机状态不等于可直接安装：恢复保留目标设备身份、账号会话、同步游标、已有凭据key与插件运行队列；不复制来源任务句柄或待处理journal。候选目录、更新回滚副本、日志、临时资源和可重建文件缓存不打包。来源新增普通表虽会被捕获，当前预检不认识的结构必须拒绝，不能静默漏恢复。

完整导出先补齐登记blob；远端不可取、文件缺失、大小/哈希错误或缺凭据key均拒绝，不能省略并称完整。捕获前在来源设备结算全部待处理阅读桶，使用正式事件身份；内部旧format1不能猜测阅读身份，明确拒绝。旧v1 JSON是另一个格式，继续保留原书库子集及非事务合并语义，不提供完整恢复的原子性承诺。

## 用户与Actor入口

`DataSyncPanel` → `useBackupActions` → `useBackupExport` / `useBackupImport` 共用已有 `HostActionFlow`。Agent `request_backup` 与插件 maintenance1.2 `requestBackup` 只定位设置按钮，用户点击后输入口令并使用原生文件对话框。Actor只能取得imported/exported/cancelled，不取得密码、文件路径、内容、任务ID或计数；状态也不证明用户选择了完整格式或已经重载。

完整导出校验口令与重复确认，捕获后释放应用写屏障，再执行原生加密保存。完整导入在屏障外解密和预检，短暂暂停生产者以固定目标快照，审阅期间恢复普通写入；最终执行必须重新检查数据库及文件版本。选择变更后需重新检查约束，再由用户确认恢复。表单取消、所属窗口关闭/组件卸载会取消自己的任务，并等待物理操作结束及清理；迟到取消不能把已保存或已提交的成功回执改称回滚。

恢复成功显示实际领域记录、文件、插件namespace及凭据计数。`full-backup-apply.ts` 在共同决定后继续持有同步→插件数据→计划/阅读/领域屏障，关闭旧插件实例，直到用户重载；旧界面不能覆盖已恢复数据。`backup/recovery-required` 同样持续暂停写入，要求启动恢复。普通提交前失败回滚后释放屏障。新导入文案提供英文与简体中文，其他语言沿用现有英文fallback。

## 固定计划与明确选择

原生 `backup_import_open` 完整认证密文EOF后执行来源SQLite结构、完整性、类型/JSON、事件身份及文件/凭据/插件基础预检。`backup_import_plan` 在同一目标读事务中固定逻辑revision、只读目标副本与事件/行/文件目录；后续当前库写入不会混进审阅。私有来源和目标连接由所属窗口Plan持有，不返回可打开的路径。

宿主分页审阅实际记录、文件、程序及凭据。每页1–100项，文件/缓存正文另限8MiB；长字段以4KiB续读，64位整数用十进制字符串，NULL、二进制、原始TEXT和内嵌NUL不经JavaScript数值转换。凭据、身份和运行状态不走通用字段展示。队列最多32个受理未完成请求，参数入队克隆、串行派发；单页取消不退役整个计划，dispose必须等在途结果及原生清理。

- 行选择绑定表、entryId及预期UUID版本，source/target/clear整批提交到私有草稿。无选择不默认覆盖，来源缺省不自动删除目标独有记录。
- “选择备份数据”是用户显式批量操作，涵盖记录、文件、插件数据及本机凭据；默认保留当前插件代码，来源独有插件只恢复数据且保持禁用。用户可随后修改单项。
- `checkRows` 在短命目标副本叠加选择，检查唯一/列约束、外键、聊天归属、虚拟绑定和别名平坦性；保留允许失去来源的软引用。错误指向原计划记录，版本变化使报告失效。constraintsPassed只证明本轮记录约束，文件/事件/程序及最终事务仍需通过。
- 同ID或HLC的不可变事件冲突会拒绝；不靠INSERT OR IGNORE或随意改ID消解。来源新事件保留原始身份，合并后所选领域状态成为新的可重放恢复事实。

## 插件与凭据

程序按侧、受管根和整树SHA256绑定，数据按整个namespace选择，不混合任意业务JSON。当前内置身份来自实际运行时目录，必须保留当前内置代码；来源的旧内置程序只能作为外装候选处理。Data-only不删除现有代码，但在同一恢复事务中将该插件禁用，避免旧代码立即运行不兼容数据。

宿主复用正常manifest解析、应用版本/能力/权限规则。来源代码在加载前必须经现有安装同意对话框确认。所选程序复制到既有候选目录，所选KV/文档/schema进入私有SQLite；真实Worker使用私有存储镜像及生产文档SQL，不注册live KV广播，不提升贡献。依据实际hasMigration规划并执行迁移、健康检查、关闭，再提交代码摘要与schema绑定结果。RPC写入先更新Worker镜像再确认，取消/失败关闭候选；同插件重试或Plan退役清理暂存。实际Tauri已验证私有KV与文档升级，以及写入后失败不泄漏到live。

凭据目录只展示槽名和存在/删除/锁定状态，内部按明文比较避免不同nonce导致假冲突。用户明确选择来源/目标本机或可解锁漫游值；选择缺省或tombstone会删除本机槽，locked候选不能选择。密封复用目标key；缺key且确需写入时生成新的目标key，通过同一journal安装，绝不克隆来源key。漫游发布义务在同一事务耐久保存，启动/重连按现有宿主时钟与生产格式发布；待发布记录阻止旧漫游投影覆盖。远端实际同步未纳入此次桌面证明。

## 共同提交、回放与崩溃恢复

`FilePlan.restore` 重验来源、目标revision、全部决定与程序迁移结果，先保存文件baseline，再在同一IMMEDIATE事务中恢复领域事件/投影、blob登记/outbox、插件namespace和本机重密封凭据/发布义务。书籍或ready封面所需文件不可用、跳过或登记不匹配则拒绝。事件附带16KiB字节块与完整摘要，恢复决定列出合并历史已知身份，重放不清除接收设备的未知记录；目标设备与会话继续保留。

`backup_restore_files.rs` 在私有 `full-restore-v1` 保存不可变旧/新文件与ready清单，然后原子替换受管blob、外部插件文件或新key。程序整树安装时删除过时文件。数据库接受记录与业务恢复在同一事务COMMIT；决定前失败或取消先回滚SQLite，再不可取消地恢复文件。文件回滚失败返回backup/recovery-required并保留恢复资料；决定后的清理失败返回成功且cleanupPending，不能谎称已回滚。

`init_db` 在blob迁移、前端水合和正常写入前恢复journal。无接受记录则还原旧文件，有接受记录则保留新文件并清理；先持久化退役目录名再删除接受记录。损坏或无法恢复的资料保留并阻止正常启动，不将混合状态交给应用。已有真实子进程COMMIT前/后exit(73)、重开数据库及文件、损坏资料修复重试、取消和写锁测试；这不是物理断电或其他操作系统的证明。

## 任务、资源与密码边界

一个应用同时只有一个原生Export/Source/Plan任务，窗口归属与阶段不匹配不能消耗任务。成功保存/apply一次性消耗就绪结果；运行中取消只发信号并等待物理结束，活动操作不按年龄强退，就绪任务十分钟闲置回收。密码在Rust使用SecretString，宿主不缓存、不写日志、不交Actor；JavaScript字符串无法保证零化。

快照/解密/审阅目录使用SQLite跨进程租约和Unix0700权限，释放/失败/启动回收；未知或错误归属留存并记录日志。它们可同时含密封值和解密材料，不能作为未加密ZIP或资源句柄交付。已经开始决定的恢复文件使用独立journal，不依赖准备目录的回收寿命。

文件流按1MiB缓冲复制；捕获至多100000成员、插件遍历100000目录项/32层、单manifest1MiB、总量512GiB，超限拒绝不截断。归档限制头/清单/成员/总量与KDF参数，拒绝路径逃逸、符号链接、特殊文件、重复/缺失成员、摘要不符和尾随数据。密文同目录临时写入后原子替换，失败保留已有目标文件。该机制不隔离同一OS用户恶意并发改文件。

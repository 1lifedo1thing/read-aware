# 完整备份实现边界

OPS08 仍未完成。当前产品导出已可选择完整加密归档或 `backup-io.ts` 的 v1 书库子集；导入仍仅支持v1。完整导出接线不等于完整合并恢复已可用，真实Tauri与组合验收仍待集中进行。

## 已实现：宿主完整加密导出任务

`full-backup-export.ts` 连接已有生产者屏障与 `backup_export.rs`，宿主先检查口令并取得原生保存目的地，再进入准备与捕获；用户输入期间没有应用写屏障。原生枚举全部未删除blob登记，宿主用当前同步范围的fetcher补齐远端/本地缺失文件，允许transport刷新凭据。任一不可用返回backup/incomplete；捕获会重新核对目录/字节，不沿用v1的省略规则。

最终捕获复用同步、插件数据、计划、阅读关闭和领域准入。原生任务持有私有快照，宿主只取得匹配taskId与format2的回执；外层屏障全部释放后，才将口令和目的地送入原生加密保存。密码在Rust中转为SecretString；JS字符串无法可靠零化，不缓存、不返回给actor。受管AppData内的目的地拒绝。保存仍沿原编解码器的同目录临时密文与原子替换。

全应用只容纳一个原生导出任务，按窗口归属校验，一次写入消耗就绪快照。运行中取消仅置标志，物理工作退出及私有目录释放前不放开任务；取消IPC早于受理时，宿主在进度和最终回执后重试。就绪任务在取消、窗口销毁或闲置十分钟后回收；此闲置期限不强退活动工作，也不替代跨进程暂存租约。失败清理记录日志并留给既有回收机制。已成功保存的原生回执不因迟到取消改称回滚。

原生真实文件/SQLite/age与宿主隔离IPC验证归属、清理、源完备性、取消、屏障释放顺序和失败结果。设置导出已经接入密码/进度UI，用户可选完整或v1，详见下节；完整导入与原子恢复尚未完成，不能把此任务当作完整备份产品交付或真实Tauri证据。

## 已实现：完整导入的宿主准备任务（内部入口）

`backup_tasks.rs` 统一Export/Source/Plan的原生所有权，一个应用同时只有一个任务。沿用窗口归属、活动工作不按年龄强退、就绪十分钟闲置回收及销毁清理。阶段检查发生在取走数据前，误用导出/来源/计划接口或其他窗口不能消耗原任务。导出继续使用同一捕获和编解码器。

`backup_import_open` 接受宿主选定文件和口令，以生产age读取器完成整个认证流后才预检SQLite/文件；返回schema/表/事件/blob/凭据/程序集计数。密码转为SecretString，解密目录及只读连接留在Source阶段；错密码、坏来源或取消都清理，不接触live DB。`backup_import_plan` 在Db锁下依次调用现有事件、实际行、文件/程序目录规划，保存Plan阶段并只回传差异计数。不存在apply IPC，也不产生imported或任何安装/恢复许可。

`prepareFullBackupImport` 完成文件选择与来源准备后，才取得现有同步→插件读取屏障→计划/阅读/领域窗口来比较目标。正常结算本机阅读事实，但不应用来源数据；此阶段使用读取模式，不无故触发导入后的镜像刷新。窗口释放后返回宿主计数review和dispose，任务ID仅在闭包中。审阅期间应用可写，计划按已有DB及文件revision再验证规则失效；最终应用必须在决定事务内重验，不能把计数视作长期有效的同意。

取消在解密、规划期间保留物理回执，避免早到cancel漏过原生准入；审阅owner取消或dispose释放原生结果，丢失宿主回执另由原生就绪回收处理。选择取消无任务；错误或不匹配回执清理。真实加密归档到全部计划验证来源与目标不变、私有数据不进报告、错阶段/归属和取消清理；隔离生产宿主证明解密不锁写、规划短暂停写、审阅恢复写。用户导入尚未切换，分页及实际字段读取已接，仍需用户领域选择界面、程序授权/迁移与原子恢复journal；真实桌面集中验收仍待进行。

## 已实现：固定计划的审阅页与程序语义检查

`backup_review.rs` 在目标仍受捕获屏障及原生Db锁保护时，把既有program_facts/credential_facts结果写入EventPlan的私有SQLite。程序manifest总大小沿用16MiB上限；凭据只存槽名、存在性/相等性、漫游及待发布状态，不存明文、密文或密钥。检查前后照常核对目标和来源，取消也继续传入原检查；缓存事务失败不发布就绪计划。

`backup_import_review` 只借用就绪计划：events是事件ID与摘要，rows是内部entryId/路由策略与摘要，files为相对路径和实际登记/可用性证据，programs与credentials从固定缓存读取。用户继续编辑后不会把后来的值混入旧计划，最终决定仍必须重验live DB/文件revision。查询不获取live Db锁或应用屏障。每页1–100条；事件ID及行摘要有既有字段界限，文件和缓存页另限8MiB条目正文，超页续游标、单条超限拒绝。无效参数/错阶段/错owner不消耗就绪结果；整个owner取消会在活动读取结束后清理。

宿主review.read在闭包中保留taskId，最多32个受理未完成请求、串行派发并克隆入队参数。单页取消仅抛弃该次结果，等待物理读取后可继续其他页；关闭review会停止新读、跳过未派发读，保留在途回执后清理原生任务。disposed表示已经停止准入，必须await dispose才表示关闭流程结算。程序完整目录经分页取得后，reviewFullBackupPrograms把提交时的选择交给已有manifest、权限、存储版本与内置程序规则；结果仍需用户授权和实际迁移，不自动信任来源代码。

### 实际记录预览与完整字段续读

事件规划在已固定的目标读事务内，通过SQLite Backup API制作同一版本的目标副本，关闭写连接后只读打开。它与来源连接、计划索引一起留在原租约私有目录中，取消、过期或销毁时先关连接再清理目录；不复制目标secret.key，也不把此数据库安装到应用。此副本包含目标数据库原有密封凭据，因此同样按私有暂存处理。WAL并发写测试证明副本不混入更新，后续live连接关闭也可继续审阅；最终应用仍必须核对live revision。

rowFields按表+计划entryId分页给字段名、主键序号及两侧值；rowField按同一身份、已知列、source/target与字节offset展开。表/列来自目录白名单，实际复合主键从内部带类型编码解出并绑定SQL参数，宿主不能提交SQL或任意键。字段页1–100列，每侧文本/二进制片段最多4096字节；原始字节base64、总byteLength和nextOffset使前缀与完整值明确区分。UTF8跨页边界缩到完整字符，非法UTF8保留原字节并返回text:null，不替换损坏字节。SQLite读取用BLOB字节长度与切片，内嵌NUL不截断；NULL与缺行不同，整数为十进制字符串，实数另带原始位型，避免JavaScript精度损失。

凭据、本机身份、阅读scratch、运行历史及blob登记的行不提供通用字段：字段页restricted=true且没有值，直接展开拒绝。它们仍需各自专用事实/恢复路由。普通设置、插件文档/私有KV及领域记录是用户数据，仅宿主审阅入口可读；这不是任意JSON的秘密识别或脱敏机制，不能转交actor。真实来源预检→规划→字段页、目标漂移、特殊类型/复合键、策略拒绝与同一任务取消清理均有定向验证。当前尚无用户领域选择界面，也未应用任何来源数据。

真实归档/SQLite验证页协议、固定时点、错误后保留、活动取消清理与大条目页界；宿主隔离IPC和选择检查验证参数快照、单页取消、关闭排空、目录完备性与原权限语义。领域可读预览/选择UI、实际授权迁移和原子恢复仍未接完，不能据此声称完整导入可用或已经真实Tauri验收。

## 已实现：绑定计划的记录选择草稿

chooseRows经backup_import_choose_rows进入同一个窗口所属Plan任务，写入的只有私有row_matches.choice与row_decision_state，既不写live数据库也不更改两侧快照。行页新增selectable、selection与decisionRevision；rowDecisions独立返回选择版本及unresolved/source/target数量，遍历可取消。审阅正文仍固定，选择元数据明确可变且带版本。草稿不跨任务/过期/取消保留，也不是崩溃恢复journal。

每批1–100条，必须提交预期UUID版本及明确source、target或clear。表和内部entryId必须匹配，重复条目、不可选择策略或过期版本使整批失败；事务中途取消也回滚已有更新。空批次拒绝，无实际变化不推进版本，真实改动换新UUID。不同页面作出的选择若基于旧版本，必须重读选择状态，不能让迟到保存覆盖新决定。

可逐行选择范围限存在来源差异的领域/聊天/历史词汇/普通设置/虚拟绑定/漫游偏好。相同记录无需选择；目标独有记录保留，来源独有记录选择target表示明确不导入，不因来源缺行推导删除。插件程序/私有namespace、凭据、身份、运行任务和文件不借此拆散专用规则。clear回到未决定；没有“缺省就是来源覆盖”。最终合并仍须检查跨记录引用、领域语义、事件身份及文件依赖；unresolved=0只是这一类草稿齐全，绝非整个恢复可执行。

宿主读取和草稿保存复用同一32操作队列并在入队时复制请求，只有原生物理回执才结束保存。单页取消仍只丢弃读取；保存没有单独的取消signal以免隐藏已经落入草稿的选择。关闭整个review会保留在途工作直到结束再清理任务。真实SQLite/加密源任务、错误后保持计划、批次回滚及宿主串行/关闭回执有定向证明，用户选择界面与实际恢复尚未启用。

## 已实现：私有原生快照

`storage/backup_snapshot.rs` 提供内部 `capture`，现由宿主专属导出任务IPC调用，不向 Agent、插件或用户交出暂存路径。调用者必须持有原生 Db 锁，并沿用 `withPluginDataBackup` 的宿主准入；捕获与目标文件计划均须显式传入由当前 AppHandle 解析的 BundledPrograms，不能默认猜测应用数据目录中的内置副本。输出对象持有带跨进程租约的私有目录；正常释放、失败和取消都会尝试回收。锁或文件系统错误阻止删除时，保留归属标记并记录日志，启动后重试。

- 捕获先确认 reading_sessions_pending 为空；未关闭时返回 backup/incomplete，不复制或丢弃无可移植身份的待结算桶。
- 在同一 SQLite 读事务中固定来源版本，使用 SQLite Backup API 按页复制所有实际表、索引和触发器。不是复制正在使用的主数据库文件，也不依赖 WAL 侧车随包移动。
- 保留事件日志、实际投影、聊天呈现状态、私有文档、本机配置和同步 bookkeeping。旧数据中日志未记录的变化也保留，不能用一次 replay 取代这份数据库。
- 清单列出所有非 SQLite 内部表的行数（包含 FTS shadow），以及独立数据库、每个登记且未删除的 blob、外装和当前解包的内置插件程序、已有 `secret.key` 的路径、字节数和 SHA-256。新增普通用户表自动进入数据库及清单。
- Blob 路径必须匹配宿主按 key 生成的受管路径。远端占位、缺失文件、坏大小或哈希不匹配均拒绝，不能默默省略并称完整。历史无哈希行会对本次复制计算哈希，不修改活库；其旧身份不能凭空恢复。
- 所有插件更新 journal 必须先结束。候选目录、更新回滚副本、日志、临时资源和可重建缓存不进入快照。普通插件存储写和领域写在原生层不能把多个数据库时点混在一起。
- 文件按 1 MiB 缓冲复制，支持块间取消；清单至多 100,000 个成员，插件遍历至多 100,000 个目录项、32 层、单份 manifest 至多 1 MiB，总捕获上限 512 GiB。超限拒绝，不截断。复制后按实际大小和登记哈希验证；准备结果另有可取消的完整性复核。
- 拒绝路径逃逸、符号链接和非普通插件文件。宿主 Db 锁阻止正常程序切换；针对另一连接的 blob 文件变化仍以登记哈希复核。不是对同一 OS 用户恶意并发改文件的隔离沙箱。
- 凭据仍以密文保存在数据库，复制已有 32 字节 key 并核实可解密。缺 key 时失败，绝不为备份创建或替换 live key。Unix 暂存目录为 0700；此处同时持有密文和解密材料，**不得作为未加密 ZIP、资源句柄或普通另存为文件交付**。

清单 format 2 是内部完整归档版本，与既有 v1 JSON 文件格式无关。它要求来源已在自己的设备上关闭全部待结算阅读桶；尚未交付用户的内部 format 1 明确拒绝，不能按时间区间猜测其阅读身份。

## 已实现：同步生产者的备份准入

`withSyncBackup` 是插件数据和阅读暂停的外层：关闭新同步工作的准入，等当前周期（含拉取后去重/漫游覆盖）、延迟书籍/封面下载、启动去重和连接/断开持久化的真实结果，再冲刷同步触发的KV与事件尾部。之后才允许备份进入插件数据屏障，避免反向阻塞正在结束的漫游覆盖。排空期间网络失败仍由同步调用方报告；已经应用的合法本地前缀可以备份，不强制联网成功。

现有v1导出/导入已接入。v1原有取书路径会按需下载缺失原文件，因此导出获得当前备份范围内的专属fetcher，下载仍使用同一引擎/加密/本地文件实现；普通下载和新周期等待释放，结束后的fetcher不可复用。范围失败或取消也须等已受理物理工作结束，不让迟到下载写进下一次操作。延后调度器任务在恢复准入时重验是否已退休。断开连接也等待凭据删除，不能删除失败却宣布本机profile已断开。

隔离宿主测试覆盖真实调度器及v1入口、插件数据锁顺序、缺失书籍下载、导入取消、事件尾部、连接延后和旧调度器退休；引擎/原生使用替身，未声称真实网络或Tauri验证。此准入不覆盖其他领域的前台/Agent/插件写者，也不是原子恢复。完整归档宿主尚须在捕获/最终决定的短暂窗口使用所有生产者屏障。

## 已实现：插件存储命令与捕获屏障

插件`storageWrite`共享独立的运行时写入完成表，KV、文档及显式延期计划命令已接；插件凭据set/remove也通过它，停止时等待真实回执。备份请求仍走read生命周期，不会被自己等待的存储完成表收进去。捕获期间新写返回backup/busy，已受理写保留原结果/失败并实际结算，再等它们产生的漫游事件。读取和Worker激活不被强制停止；迁移自己的KV/文档写仍合法，凭据权限不放宽。

导出现在在插件迁移互斥下先准备缺失书籍文件，此时允许运行时数据与设置写，避免插件transport刷新token被捕获屏障阻挡。准备只查本地文件元数据/下载，不把原文复制两遍；结束或失败时同步关闭写准入、排空已受理写，之后才开始阅读关闭和备份捕获。捕获调用明确只读本地字节，准备成功后丢失文件、或出现新的缺失书籍返回backup/changed；初次就无法取得的文件保留v1既有省略行为，仍不能称完整备份。

隔离生产context测试覆盖发起备份的插件、KV/文档/凭据忙写、停止与取消、迁移不越权；同步/导出测试另验证准备下载经同一运行时准入刷新凭据。没有真实Worker/Tauri验收，这一层自身不暂停计划或领域生产者；下节记录它们的后续接线，完整归档仍须统一其余来源。

## 已实现：自主计划的状态写入暂停

备份捕获在插件数据屏障内先取得`PluginScheduleController.withPersistencePaused`，再关闭阅读事实。它同步停止新执行、手动控制及延期命令，周期sweep跳过；已派发状态写实际结束后才能捕获。不会等待完整callback，因为callback本身可能请求备份。已运行任务在捕获期间完成时，最后状态补丁在队列中等待释放，再校验原绑定token；停用/替换不允许旧结果写入新实例。未执行的排队任务没有丢失，下一次sweep正常继续。

## 已实现：领域事务、设置与凭据的共同准入

`DomainWriteGate` 记录短暂的本地决定：从事件身份/HLC准备，经原生条件事务直到成功广播。普通事件commit/append以及画像初始化/条件编辑、实体决定、身份整理与scratch、onboarding、分类/摘要、记忆编辑/维护、书籍合并、批注条件编辑、上下文发布、恢复凭据再发布都接入。已有revision、权限和取消规则不变；这些回执也进入关机结算。模型推理、上下文来源与插件callback不登记为事务，因此来源可以请求备份，之后再尝试最终发布。

排空阶段继续接纳写入，直到已受理操作及它们同步触发的后续事件全部结算；在该静止点同步关闭准入，随后新事务返回`backup/busy`，不排队重放旧候选。不能先关闭事件准入再排空KV：设置/凭据的物理写会在成功后产生漫游事件。因此KV写队列（含batch/replace）、本机与插件凭据也共用该准入。受理时仍同步更新原有乐观镜像，拒绝时不派发IPC，沿既有日志/`local-write-failed`表面通知；KV重发当前值让同步UI setter的本地乐观状态回正。

`withBackupCapture` 统一最终顺序：在同步/插件数据准备与排空后，保留计划状态暂停，再关闭阅读事实，最后取得领域窗口。v1画像读取需要的一次性初始化、画像恢复与KV恢复显式传入当前范围的写函数，没有ambient放行标志。普通调用者不能借同一时刻的备份写权限；范围退出后函数失效，失败/取消仍等已派发原生恢复写真正完成。导入原有非事务合并语义不变。

## 已实现：文件、派生文本与聊天展示写入

Blob写入复用领域准入：小文件raw、桌面大文件分块和既有base64兼容分块从受理到物理提交保持同一回执。失败后等待`blob_write_abort`结束再释放，清理失败日志不覆盖原失败；删除字节/registry也经过该边界。文本缓存的读写走相同`booktext:` blob入口，提取管线继续按原版本/取消规则运行，其捕获期写入被拒绝而不是悄悄落地。

原生`blob_write_open/chunk`只修改内存buffer（`storage/blobs.rs`），增量writer因此在open与最终commit分别申请准入，不用备份等待外部数据提供者。已准备流在捕获期不能commit，仍可abort释放内存；真实同步下载继续由外层SyncWorkGate持有整个网络寿命。没有改变分块协议或声称该buffer本身是文件快照。

聊天保存捕获一份消息候选用于事件与展示写入，保留从事件差异准备到`ai_chat_replace`的完整回执；无新增事件、只有`parts_json/error`变化时也受限。清空保留事件和`ai_chat_clear`清除错误stub的回执。v1书籍/文件、收藏夹和批注原始恢复显式传入本次备份范围写函数，普通恢复调用依旧被拒绝；取消不释放已经派发的恢复写。v1仍为非事务子集合并。

## 已实现：有租约的私有暂存与启动回收

`backup_staging.rs` 将快照、认证解密结果与事件计划的目录统一为 `BackupDirectory`。生产捕获、解密和规划接口只接受 `BackupStaging`，由原生启动根据应用数据目录创建并放入 Tauri state；不再接收任意暂存 Path。合成路径和无租约的认证输入夹具只存在于 cfg(test)。当前 AppData 下的 `backup-staging-v1` 是暂存协议目录，与归档 format 2 / 既有 v1 JSON 无关。

- 每个随机命名的目录先创建带 application_id/user_version 的独立 SQLite 租约文件，并持有 EXCLUSIVE 事务，之后才允许写入私有数据库、凭据 key 或解密字节。租约随对象所有权进入来源预检、行/文件计划，最后释放；通过已有 SQLite 的跨进程文件锁判断活跃状态，不采用 PID、心跳或过期时间猜测，也没有新增锁依赖。
- 创建、清理和租约最终退役共用 `.control/registry.sqlite` 的排他锁，避免清理器抢在创建者完成初始化之前删除目录。租约忙表示仍在使用，原样保留。注册锁忙或文件系统失败时不阻塞 UI/伪报成功，返回现有 db/locked 或记录后台日志，目录保留以便重试。
- 原生 setup 在数据库初始化前注册暂存管理器并启动后台回收，不阻塞主窗口或数据库恢复。只处理专用根下格式匹配的目录及可验证的本协议租约；陌生文件、错误标记、缺标记却有正文的目录和符号链接保留并报告。根扫描至多 10000 项；空的未初始化目录可清除。不会扫描或删除任意系统临时目录。
- **正文先删，租约最后退役。** 清理全程持有注册锁，逐项删除正文时保留租约；所有正文清空后关闭租约连接，再删标记和空目录。清理中断或文件删除失败后仍可在下一轮确认归属；在最后一步退出只会留下空目录。正常 Drop 使用相同顺序，避免 TempDir 在失败时先删租约。连接先于所属目录关闭，兼容 Windows 的打开文件约束，实际跨平台故障仍待集中验证。
- Unix 根、控制目录和暂存目录均为 0700；租约与控制文件不进入加密归档或源数据库，也不属于同步数据。捕获清单明确排除私有备份暂存。此目录只承载可丢弃的准备结果，**不得用作已作出恢复决定的 journal 或跨重启恢复文件**；后续原子恢复必须先将其所需内容交给独立耐久位置。

真实子进程持有含合成凭据的暂存目录，父进程回收确认其仍活跃；终止并等待子进程退出后再次回收成功。另验创建/清理注册锁互斥、正常释放、锁忙延后、中途删除失败后保留租约并重试、陌生/缺失标记与符号链接保留、0700 权限。真实口令归档往返中，解密→只读预检→事件计划持续保留源租约，同时计划目录有独立租约；释放计划后两者清理，快照租约不进入 manifest。相关快照、归档/预检/计划回归及原生编译通过；未提前执行集中 Tauri、实际 Windows/Linux 或无关前端检查。

## 已实现：认证加密归档编解码

`storage/backup_archive.rs` 与 `backup_archive_read.rs` 是内部编解码器；导出已由宿主任务IPC调用，认证解密与目标计划已接内部宿主任务，导入应用尚未接通。使用 [age 的口令加密流](https://docs.rs/age/latest/age/) 包裹 tar；数据库、清单、文件名、插件程序及已有凭据 key 全在加密载荷内，不产生中间明文 tar。

- 写入目标同目录的临时密文文件；逐成员核对快照大小和 SHA-256，完成 tar、age 最终认证标签并同步文件后才替换目标。取消、来源篡改或写入失败不会先截断旧备份。
- 口令使用零化的 `SecretString`，要求至少 12 个字符、至多 1024 UTF-8 字节。写入 scrypt work factor 为 18，读取拒绝更高值；age 首次构造另有机器默认值校准，不能据此声称整个进程严格限制为一次 KDF 的资源量。校准和单次 KDF 无法中途取消，前后及文件处理块间检查取消。
- 读取限制 age 头为 64 KiB、密文为 512 GiB 加 2 GiB 元数据空间；清单至多 32 MiB、100,000 成员、路径 8192 字节、声明文件合计 512 GiB。tar 原始模式仅接受普通文件和有界 GNU 长路径，拒绝链接、PAX、稀疏等其他成员类型；不信任文件权限或外部路径。
- 先验证清单与路径，逐块解密至私有临时目录；成员必须唯一、大小及 SHA-256 匹配，不允许未声明/缺失成员、大小写碰撞、父文件重叠、Windows 设备名或路径逃逸。文件用 create-new 创建，文件系统别名碰撞不能覆盖已有成员。
- tar 结束后继续读到 age 认证 EOF，拒绝截断、损坏、非零尾随数据或拼接归档。只有完整通过才返回 `AuthenticatedBackup`；失败、取消、正常释放清理暂存目录。此阶段不会打开 SQLite，也不会修改活库。**密码认证和文件哈希通过不等于数据库结构、事件身份或应用语义可信**。
- 稳定错误码区分归档结构、解锁失败和口令规则，八语言只显示本地化提示。过高 KDF 开销按 age 的类型化错误映射，不调用其可能发生整数下溢的时长文案格式化；没有修改依赖或放宽上限。

`backup_event_plan.rs` 的 `plan_events` 消费预检后的来源，并在一个目标读事务中计算数据库版本和所有事件匹配。结果拥有来源及私有计划库，正常释放、失败和取消会清理；没有目标写入、重放或恢复许可。

- 分别按事件 ID 和完整 HLC 查询目标，保留 new / existing / ID conflict / clock conflict / both 五种结果。相同 ID 只有整个不可变 envelope 相同时才视为已存在；另一 ID 占用相同 HLC 不能被去重吞掉，两个键同时冲突会同时记录。
- 比较全部 envelope 字段及 payload，排除每台设备自己的 ingested_at。payload 按 JSON 值比较：忽略空格和对象键顺序，规范化 1 / 1.0 / 1e0 与正负零；不经 f64 转换归一化大整数，保留数组顺序、类型和来源字段差异。坏目标 JSON 或身份读取失败会报错，不能等同于目标不存在。未知事件仍是保留事实，匹配不证明其领域语义有效。
- 来源逐条扫描，目标按两个索引查找；私有 SQLite 计划只记录 ID、分类和摘要，不复制正文/密钥。分页至多 100 条，续页按主键 seek，不把整个日志或冲突清单堆入内存。调用者提供取消检查；SQL 行间及大字段每 1 MiB、JSON 节点间检查，单条事件 JSON 仍有 64 MiB 上限。计划不承担跨重启恢复日志的职责。
- 目标版本是带类型和长度边界的 SHA-256 摘要，覆盖 schema、所有实际表（含私有/本机/统计及 FTS shadow）与隐式 rowid。保留 BLOB/TEXT、NULL/空串等区别，不只比较行数或最新 HLC；不带 rowid 的表按主键排序。结构变更、同条数更新、私有设置、设备身份变化都会使旧计划失效，属于保守的全库检查。
- `verify_target` 必须在将持有最终数据库决定的事务内调用，优先 IMMEDIATE；检查之后不能释放事务再写。变化返回已有 backup/changed，要求重新规划。第二个真实 WAL 连接在规划期间修改事件时，计划仍使用同一旧视图，后续目标检查拒绝它。

此阶段只关闭事件身份识别及数据库预览过期检查的基础缺口。冲突尚未消解；没有事件或实际投影被导入。数据库版本不包含磁盘文件字节或运行时状态，完整流程还需文件版本、运行时排空和宿主确认。后台读取引起的持久 bookkeeping 变化也可能使计划过期，不能据此省略后续静止窗口设计。

## 已实现：实际数据差异与处理方式

- 计划库只新增复合键与摘要，不复制行正文或凭据值；键自身可能含个人数据，仍只存于原私有暂存目录，不开放资源句柄。按表和自增 entry_id 主键续页，最多 100 条，分页不返回原始键或值。计数、摘要及差异汇总逐行检查取消，避免长 SUM/count 聚合遮住取消；失败与释放清理整个私有来源/计划，不写目标。

## 已实现：凭据比较与重新密封准备

`FilePlan.credential_facts` 在数据库/文件版本复核后枚举当前两侧本机凭据、漫游投影及待发布记录；`prepare_credentials` 对完整目录中的每一项要求明确选择来源本机、来源漫游、目标本机或目标漫游。来源缺行不能自动删除目标；明确选择一侧本机的缺省值或漫游 tombstone 才生成删除操作。目录不含 sync.* 本机身份，额外/遗漏选择拒绝；漫游仍遵循现有 ai-api-key 前缀契约，未知漫游类型不得静默当普通设置写入。

## 已实现：耐久凭据发布与启动保护

Schema 42 的 `restored_credential_publications` 是仅存 slot/创建时间的本机操作记录，无凭据值，不是跨设备投影。`PreparedCredentials.enqueue_publications` 要求与最终本机凭据写入处于同一恢复事务；不会将来源队列直接克隆。凭据目录也枚举两侧队列，保留“只有待发布删除、没有 KV 或漫游行”的恢复选择。通用 RowPlan 将原队列分为保留当前设备的运行状态；重放不清除，wipe 清除。

- 原生 pending 最多返回 100 个 slot；publish 接受最多 100 个宿主新生成的 envelope，并按累计 16 MiB 明文控制密文回执体积（单个更大的合法值独立发布，余项保留给后续批次），只处理仍有记录的 ai-api-key 项，拒绝非本机身份、非 system/preference 事件与重复项。内容不信任调用方：在 Db 锁和 IMMEDIATE 事务内重读当前本机凭据与当前 master key，按既有格式密封/生成 null，沿正式 commit_events_in_transaction 追加日志、更新投影/同步 outbox，并删除待发布记录。任何一步失败全事务回滚；重复调用/丢失回执后已完成 slot 是无操作，不重发旧值。
- 缺 master key 时保留记录；用户在离线恢复后又改值或删除，发布时采用最新已保存值，不保留第二份旧明文/密文快照。准备阶段不再提前生成漫游 payload，避免留下可以误用的旧 key/旧值；在线与离线都走同一耐久发布器。
- preferences_load_all 在记录尚存时排除对应旧漫游行，避免启动或同步覆盖掉已恢复的选择。宿主在启动/刷新覆盖前、连接后 republish 前及每个同步周期拉取前尝试排空；等待已有凭据写完成，复用同一进行中的任务，只有原子提交成功后广播真实已写入事件。失败沿现有启动/同步日志和错误路径处理，记录留下重试。
- 发布先重读持久化日志/检查点 frontier，再用原有 JS HLC 分配器生成 envelope，避免引入第二个本机时钟分配器。事务发现竞争时返回 backup/changed，最多三次重新读取/分配；持续竞争保留记录并返回失败。新 IPC 不返回明文/key，不开放给 Agent/插件为任意 slot 创建记录。

针对真实 WAL 文件重开验证记录留存、缺 key 保留、用户后续值优先、删除 null、事件/投影/outbox/记录退役原子性、故障回滚、旧时钟与伪造 envelope 拒绝、重复回执、大值批次保留未发布尾部、重放保留与 wipe 清除。宿主定向覆盖等待凭据持久化、共享进行中的调用、提交后广播、失败重试与 HLC 重取；已有凭据顺序回归、schema 42 行规划/来源预检以及 web/desktop 类型检查通过。未做集中真实 Tauri 验收；完整恢复事务尚未调用这些准备与入队操作，产品导入仍为 v1，完整导出已另行接线。

## 已实现：捕获与合并规划前关闭本机阅读事实

`backup_close_reading_sessions` 是宿主内部 IPC，`closeReadingSessionsForBackup` 是严格准备函数，现经withBackupCapture接入内部完整导出任务。待结算桶仅以书籍/本地日期/小时定位，没有跨设备事件身份；因此在来源设备捕获前、目标设备合并规划前先关闭自己的桶，使用既有 `book.sessionRecorded` 事件 ID 去重，不依据重叠时间猜测已导入量。

- 宿主读取待结算目录，重读持久 frontier 后使用原有 JS HLC 分配器生成 system/book envelope；与凭据发布共用此入口。原生持有 Db 锁，在 IMMEDIATE 事务内重读实际目录、最新时间与位置，不采用调用者旧 payload。目录必须完整匹配，本机新时钟必须合法；竞争返回 backup/changed，宿主最多重读三次，持续失败直接返回。
- 正式事件追加、投影/outbox 更新与桶退役复用原有 reading_session_flush 的同事务实现；任一失败全部回滚。零时间但有位置的桶仍生成事实；仅零时间且无位置的空桶可以清除。读取至多 100000 桶，书籍/日期/位置文本累计至多 64 MiB，超限拒绝。
- 只广播原生成功回执中的实际事件。全部已关闭后的请求重试不产生第二份事实；关闭后又有新的活动时，旧 ID 不得关闭新桶。后续导出失败不撤销已经成立的阅读事件；原有事件身份确保重复追加不重复累计。
- format 2 捕获、认证后来源预检和目标事件规划分别要求待结算表为空。即使归档哈希有效，含待结算行仍拒绝；捕获前出现新的阅读活动也拒绝。旧内部 format 1 尚未用户交付，直接拒绝，不静默丢弃或猜测转换。
- **阅读队列的可释放暂停已接通。** `withReadingBackup` 先同步采样当前计时，保留队列位置并等待已受理观察实际完成，再调用原子关闭并执行调用方IO。备份期间的计时/位置、切书及旧会话退休排在保留位置之后，释放才写；采样器继续使用，不把备份耗时误作停读，也不丢弃用户的新观察。准入失败/取消/操作失败均释放；排空中的取消仍等物理工作结束，已开始的IO保留真实结果。
- 现有v1导出/导入已经通过这一边界，文件格式仍是v1子集。定向验证使用生产入口、实际阅读队列及原生IPC替身，尚非真实Tauri验收。完整归档的宿主后续必须在实际捕获/规划或最终决定的静止窗口复用它；不能跨密码/选择等用户等待长期占用，也不能把它当作其他领域/插件/原生写者的统一准入或完整恢复已完成。
- 排空期间写失败会拒绝本次备份并保留既有错误报告；过去已经报告、未落库的观察不可能由备份恢复。暂停不重试失败的观察，也不改写其身份。

定向测试覆盖最新累计时间/独立位置时钟、位置独有桶、回执重试、旧身份拒绝、新活动导致捕获拒绝、整批故障回滚和既有事件去重。目标规划拒绝未关闭桶且不修改目标/不遗留来源目录；认证预检拒绝含待结算数据的 format 2。真实口令格式往返、原有阅读结算和快照回归以及宿主回执/有限重试、凭据共享时钟回归、web/desktop 类型检查用于验证此单元；未提前运行集中真实 Tauri 验收。

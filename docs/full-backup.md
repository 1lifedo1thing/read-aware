# 完整备份实现边界

OPS08 仍未完成。当前产品入口继续使用 `backup-io.ts` 的 v1 子集，不能把下述原生基础当作已经可用的完整备份或合并恢复。

## 已实现：私有原生快照

`storage/backup_snapshot.rs` 提供内部 `capture`，尚未注册 IPC，也不向 Agent、插件或用户交出暂存路径。调用者必须持有原生 Db 锁，并沿用 `withPluginDataBackup` 的宿主准入。输出对象拥有临时目录；正常释放、失败和取消均删除该目录。

- 在同一 SQLite 读事务中固定来源版本，使用 SQLite Backup API 按页复制所有实际表、索引和触发器。不是复制正在使用的主数据库文件，也不依赖 WAL 侧车随包移动。
- 保留事件日志、实际投影、聊天呈现状态、私有文档、本机配置和同步 bookkeeping。旧数据中日志未记录的变化也保留，不能用一次 replay 取代这份数据库。
- 清单列出所有非 SQLite 内部表的行数（包含 FTS shadow），以及独立数据库、每个登记且未删除的 blob、外装和当前解包的内置插件程序、已有 `secret.key` 的路径、字节数和 SHA-256。新增普通用户表自动进入数据库及清单。
- Blob 路径必须匹配宿主按 key 生成的受管路径。远端占位、缺失文件、坏大小或哈希不匹配均拒绝，不能默默省略并称完整。历史无哈希行会对本次复制计算哈希，不修改活库；其旧身份不能凭空恢复。
- 所有插件更新 journal 必须先结束。候选目录、更新回滚副本、日志、临时资源和可重建缓存不进入快照。普通插件存储写和领域写在原生层不能把多个数据库时点混在一起。
- 文件按 1 MiB 缓冲复制，支持块间取消；清单至多 100,000 个成员，插件遍历至多 100,000 个目录项、32 层、单份 manifest 至多 1 MiB，总捕获上限 512 GiB。超限拒绝，不截断。复制后按实际大小和登记哈希验证；准备结果另有可取消的完整性复核。
- 拒绝路径逃逸、符号链接和非普通插件文件。宿主 Db 锁阻止正常程序切换；针对另一连接的 blob 文件变化仍以登记哈希复核。不是对同一 OS 用户恶意并发改文件的隔离沙箱。
- 凭据仍以密文保存在数据库，复制已有 32 字节 key 并核实可解密。缺 key 时失败，绝不为备份创建或替换 live key。Unix 暂存目录为 0700；此处同时持有密文和解密材料，**不得作为未加密 ZIP、资源句柄或普通另存为文件交付**。

清单 format 1 是内部快照清单版本，与既有 v1 JSON 文件格式无关。

## 已实现：认证加密归档编解码

`storage/backup_archive.rs` 与 `backup_archive_read.rs` 是内部编解码器，尚未注册 IPC 或接入用户密码流程。使用 [age 的口令加密流](https://docs.rs/age/latest/age/) 包裹 tar；数据库、清单、文件名、插件程序及已有凭据 key 全在加密载荷内，不产生中间明文 tar。

- 写入目标同目录的临时密文文件；逐成员核对快照大小和 SHA-256，完成 tar、age 最终认证标签并同步文件后才替换目标。取消、来源篡改或写入失败不会先截断旧备份。
- 口令使用零化的 `SecretString`，要求至少 12 个字符、至多 1024 UTF-8 字节。写入 scrypt work factor 为 18，读取拒绝更高值；age 首次构造另有机器默认值校准，不能据此声称整个进程严格限制为一次 KDF 的资源量。校准和单次 KDF 无法中途取消，前后及文件处理块间检查取消。
- 读取限制 age 头为 64 KiB、密文为 512 GiB 加 2 GiB 元数据空间；清单至多 32 MiB、100,000 成员、路径 8192 字节、声明文件合计 512 GiB。tar 原始模式仅接受普通文件和有界 GNU 长路径，拒绝链接、PAX、稀疏等其他成员类型；不信任文件权限或外部路径。
- 先验证清单与路径，逐块解密至私有临时目录；成员必须唯一、大小及 SHA-256 匹配，不允许未声明/缺失成员、大小写碰撞、父文件重叠、Windows 设备名或路径逃逸。文件用 create-new 创建，文件系统别名碰撞不能覆盖已有成员。
- tar 结束后继续读到 age 认证 EOF，拒绝截断、损坏、非零尾随数据或拼接归档。只有完整通过才返回 `AuthenticatedBackup`；失败、取消、正常释放清理暂存目录。此阶段不会打开 SQLite，也不会修改活库。**密码认证和文件哈希通过不等于数据库结构、事件身份或应用语义可信**。
- 稳定错误码区分归档结构、解锁失败和口令规则，八语言只显示本地化提示。过高 KDF 开销按 age 的类型化错误映射，不调用其可能发生整数下溢的时长文案格式化；没有修改依赖或放宽上限。

## 已实现：只读结构与来源一致性预检

`backup_preflight.rs` 接受 `AuthenticatedBackup`，返回拥有私有归档和已固定读事务的 `PreflightedBackup`。结果只供内部合并规划，不是恢复许可或最终回执。当前只接受本构建 schema 41；不在导入副本上运行迁移，也不执行它的 DDL 到活库。

- 打开前要求独立 rollback-mode SQLite 文件，拒绝需 WAL 侧车的输入。连接为只读，配置 defensive、trusted_schema=OFF、禁用触发器/视图、query_only、禁用 mmap；不注册应用函数，不启用扩展加载，附加数据库上限为零。采用 [SQLite 对不可信数据库的防护建议](https://www.sqlite.org/security.html)。
- 先做完整 integrity_check，再和现有迁移在空库生成的结构逐项比较，覆盖表、索引、触发器、FTS 与 shadow，逐条核对完整迁移记录，不将任意长度的来源记录列表收集入内存。额外对象、缺失/改写结构拒绝；不会跳过未知用户表。空的旧 blobs 表及 SQLite 自己生成的 sqlite_stat1/4 允许正常缺省，后者若存在仍比对结构。
- 逐行检查 SQLite 实际值类型、非空/主键、UTF-8 和持久 JSON，实际全表计数必须匹配清单。app_kv 仍按原契约保留插件任意字符串和密封凭据，不强迫其内容为 JSON；不重放、不要求实际投影与事件相等。
- 核对事件版本、非空身份、JS 安全整数 HLC 和对象 payload。原 schema 唯一约束加 integrity_check 保证来源内事件 ID/HLC 唯一；未知事件类型原样保留，尚不宣称其 payload 领域语义已验证。声明外键与消息→线程引用检查；可随删书继续存在的插件文档出处等不擅自改成级联关系。
- 未删除 blob 登记必须和认证成员一一匹配受管路径、大小/已有哈希；额外 blob 或缺失成员拒绝。实体书必须有原文件，ready 封面必须有登记文件；虚拟书必须有格式正确的内容绑定，不把缺失/禁用提供者冒称可读或离线可用。
- 校验已有凭据 key 可解密、插件目录身份和 manifest 的 schemaVersion、私有文档 owner 及宿主存储版本。凭据使用只读 `decrypt_existing`，正常捕获也复用它；缺失/坏 key 不会创建或修复。未结束的插件更新 journal 拒绝。程序与目标存储版本的兼容、权限/完整 manifest 验证及迁移仍归后续宿主恢复流程，不激活来源程序。
- SQLite 单行/值上限 64 MiB、SQL 长度 256 KiB、列数 128、表达式深度 64、结构对象 4096、结构文本合计 4 MiB；整个预检有五分钟处理期限，每 1000 条 SQLite VM 指令和 Rust 行/文件间检查取消。这里不是整个进程的严格内存上限。超限/结构问题使用已有 backup/invalid-archive，取消保留 backup/cancelled，本机文件和锁错误保留原有 fs/* / db/locked，避免误称备份损坏。成功移除该阶段计时器，读事务留给下一阶段，失败或释放关闭连接后清理目录。

定向用例保留日志未记录的历史记忆、聊天呈现 error、未知事件及已删书的插件文档出处；验证 VACUUM/ANALYZE 后正常接受。读连接写入、ATTACH、扩展加载拒绝，源数据库字节未改且无 WAL 侧车。恶意视图/触发器、额外表、缺索引、伪迁移、坏类型/JSON/HLC、坏引用/文件登记、更新未决、伪计数/密钥/插件身份、取消和 SQL 中断拒绝并清理。

## 已实现：事件匹配计划与目标数据库版本检查

`backup_event_plan.rs` 的 `plan_events` 消费预检后的来源，并在一个目标读事务中计算数据库版本和所有事件匹配。结果拥有来源及私有计划库，正常释放、失败和取消会清理；没有目标写入、重放或恢复许可。

- 分别按事件 ID 和完整 HLC 查询目标，保留 new / existing / ID conflict / clock conflict / both 五种结果。相同 ID 只有整个不可变 envelope 相同时才视为已存在；另一 ID 占用相同 HLC 不能被去重吞掉，两个键同时冲突会同时记录。
- 比较全部 envelope 字段及 payload，排除每台设备自己的 ingested_at。payload 按 JSON 值比较：忽略空格和对象键顺序，规范化 1 / 1.0 / 1e0 与正负零；不经 f64 转换归一化大整数，保留数组顺序、类型和来源字段差异。坏目标 JSON 或身份读取失败会报错，不能等同于目标不存在。未知事件仍是保留事实，匹配不证明其领域语义有效。
- 来源逐条扫描，目标按两个索引查找；私有 SQLite 计划只记录 ID、分类和摘要，不复制正文/密钥。分页至多 100 条，续页按主键 seek，不把整个日志或冲突清单堆入内存。调用者提供取消检查；SQL 行间及大字段每 1 MiB、JSON 节点间检查，单条事件 JSON 仍有 64 MiB 上限。计划不承担跨重启恢复日志的职责。
- 目标版本是带类型和长度边界的 SHA-256 摘要，覆盖 schema、所有实际表（含私有/本机/统计及 FTS shadow）与隐式 rowid。保留 BLOB/TEXT、NULL/空串等区别，不只比较行数或最新 HLC；不带 rowid 的表按主键排序。结构变更、同条数更新、私有设置、设备身份变化都会使旧计划失效，属于保守的全库检查。
- `verify_target` 必须在将持有最终数据库决定的事务内调用，优先 IMMEDIATE；检查之后不能释放事务再写。变化返回已有 backup/changed，要求重新规划。第二个真实 WAL 连接在规划期间修改事件时，计划仍使用同一旧视图，后续目标检查拒绝它。

此阶段只关闭事件身份识别及数据库预览过期检查的基础缺口。冲突尚未消解；没有事件或实际投影被导入。数据库版本不包含磁盘文件字节或运行时状态，完整流程还需文件版本、运行时排空和宿主确认。后台读取引起的持久 bookkeeping 变化也可能使计划过期，不能据此省略后续静止窗口设计。

## 已实现：实际数据差异与处理方式

`EventPlan.plan_rows` 接续原事件计划，在新的目标读事务中先验证原数据库摘要，再生成 `RowPlan`。因此两段计划针对同一逻辑目标版本；行规划期间的第二个 WAL 连接变化不会混入当前读视图，最终决定前仍会被原版本检查拒绝。

- 当前源/目标的每张实际表都有处理方式，包括事件投影、聊天、插件私有文档、旧 vocabulary_entries、普通设置、凭据、虚拟书绑定、文件登记、未结算阅读、本机状态及派生索引。新增未知表会失败，不默默遗漏。事件身份继续使用上一阶段；schema/索引/检查点/本机版本钟等明确交给校验或重建；未完成插件更新 journal 和未迁出的 inline blobs 拒绝。
- 有数据责任的普通表按真实复合主键生成带类型/长度的二进制身份，保留空串和 NUL，不用字符串分隔符拼键。源与目标逐行写入同一私有计划库，记录 source-only / target-only / same / different；没有根据缺行推断删除，也没有选择胜方。摘要反映实际 SQLite 值，JSON 字面格式变化在这里仍是存储差异，不等同于领域冲突。
- 聊天 seq、parts_json 和 error 均进入实际差异；不因它们不在日志投影中而省略。插件文档 revision 不参与内容摘要，但保留完整摘要以单独报告 generated-only；后续通过正式写入生成新的并发身份，不将旧 revision 当作应覆盖的业务字段。
- app_kv 按键分流：设备迁移标记、sync 会话/传输状态保留当前设备；普通凭据必须重新密封；插件 KV/schema 成组处理，schedule-state/runs 归运行历史处理；虚拟书绑定需要与书和提供者协调。synced_preferences 的 secret:* 归跨密钥翻译，不可直接复制旧漫游密文。私有 KV 的任意字符串保持原样。这里的处理类别不是每行新增用户审批，也不代替后续领域合并逻辑。
- 未结算 reading_sessions_pending 明确要求转换/去重已读事实，不能当作可丢缓存；运行任务/历史也不能直接恢复成当前进程可执行的句柄。blob_objects 只做登记差异，实际字节和程序目录的匹配仍待后续文件计划。
- 计划库只新增复合键与摘要，不复制行正文或凭据值；键自身可能含个人数据，仍只存于原私有暂存目录，不开放资源句柄。按表和自增 entry_id 主键续页，最多 100 条，分页不返回原始键或值。计数、摘要及差异汇总逐行检查取消，避免长 SUM/count 聚合遮住取消；失败与释放清理整个私有来源/计划，不写目标。

定向验证覆盖当前全部表的分类、历史记忆两边独有/相同/不同、聊天呈现、旧生词、插件 revision、复合键分隔符/NUL、不复制凭据正文、分页、真实 WAL 并发、计划插入之后取消和无目标写。此阶段没有实际合并选择、字段级语义解释、文件计划、冲突解决或恢复提交。

## 已实现：文件与程序目录差异

`RowPlan.plan_files` 在目标读事务内重验事件/行计划的数据库版本，接续目标受管文件扫描，返回拥有原行计划的 `FilePlan`。复用原快照的有界文件收集器，新增只读扫描模式；目标扫描不复制文件，不创建凭据 key，不写数据库。

- 文件比较使用真实长度与 SHA-256，分页最多 100 条；源独有、目标独有、相同、不同分别记录，双方均无本地字节的登记项明确为 unavailable。目标 `blob_objects` 与实际文件交叉检查：正常本地、未下载、登记为本地但缺文件、登记摘要不符、未登记实际字节分别保留。缺失或不符可以进入后续修复选择，不谎称为空或已恢复；目标孤儿文件也不能被源静默覆盖。
- 外装和内置插件按各自整个目录生成摘要，包含相对文件名、长度和内容摘要，同时记录 manifest 的 schemaVersion。相同版本号但字节不同仍为差异；不逐文件混装两个程序。此处只核对基本程序身份/存储版本，完整 manifest、权限、程序选择及私有数据迁移仍须沿宿主安装流程处理，不执行插件代码。
- 目标 secret.key 纳入文件版本，类别始终为保留当前设备密钥；旧凭据仍需在后续领域处理重新密封。仅比较 key 文件不等于已经完成凭据翻译。
- 目标扫描包含整个受管 blob 目录和激活程序目录；隐藏候选/回滚目录沿用快照排除规则。受管文件与遍历项上限 100000、注册 blob 上限 100000、1 MiB 流式哈希、文件总字节上限 512 GiB、程序深度 32；链接/非普通文件和大小写路径冲突拒绝。清单解析有界，空目录遍历与流式哈希均可取消；来源重新核验也拒绝读取中增长的成员。
- `verify_target` 必须在最终决定的数据库事务及宿主运行时/文件写入屏障内执行：重验全库版本并重新扫描文件，文件增删/同大小改写/密钥变化均使旧计划失效。文件扫描本身不提供操作系统原子快照，也不锁住外部进程；后续文件暂存、原子决定与崩溃恢复仍必须处理该边界。`verify_source` 可重验私有来源的非数据库成员，不能把此前预检当成永久有效。

定向验证包括真实 blob 登记与文件差异、目标未下载/缺失/损坏/孤儿文件、整目录程序差异、保留密钥、稳定分页、仅文件变化使计划过期、私有来源篡改、取消释放、按块中断、悬空链接及跨来源大小写路径冲突。共享收集器的原完整快照回归通过。仍无任何文件应用、冲突选择或完整恢复回执。

## 已实现：凭据比较与重新密封准备

`FilePlan.credential_facts` 在数据库/文件版本复核后枚举当前两侧本机凭据和漫游投影；`prepare_credentials` 对完整目录中的每一项要求明确选择来源本机、来源漫游、目标本机或目标漫游。来源缺行不能自动删除目标；选择目标本机的缺省值或明确的漫游 tombstone 才生成删除操作。目录不含 sync.* 本机身份，额外/遗漏选择拒绝；漫游仍遵循现有 ai-api-key 前缀契约，未知漫游类型不得静默当普通设置写入。

- 在私有原生处理内按明文比较本机凭据，消除每次随机 nonce/不同设备 key 导致的假冲突；同时记录同一设备本机值与漫游值是否不同，不猜测哪一个更新。报告仅有名称、存在/删除/锁定状态和相等关系，无明文值。旧同步 key 不可用或密文无法认证时，漫游候选标记 locked；仍可明确选择正常的本机值，选择 locked 候选则失败。
- 本机写入准备复用 `secrets.rs` 的 AES-256-GCM 编码，使用当前设备 key；没有现有 key 且确需写值时只在内存生成新 key，零化保护并交后续原子安装。删除全部凭据不会创建 key。不会调用常规 first-use 创建逻辑、覆盖 live key、克隆来源账号会话或同步主密钥。
- 漫游密封严格沿用 `sync-envelope.ts` 的 v1 XChaCha20-Poly1305、24 字节随机 nonce 和绑定 slot 的 AAD；已有依赖提升为直接依赖，没有升级依赖版本。当前目标有 master key 时生成 **新的 preference.changed payload**，删除为 null。旧来源事件 ID/HLC/payload 原样保留，不能原地改密文。后续提交必须先合入/推进历史时钟，再为这些 payload 分配新身份与 HLC，以免旧事件重新覆盖已选值。
- 目标离线且没有 master key 时，准备本机密文/删除并标注 `PendingConnection`。后续恢复决定必须耐久保存并在连接后完成发布；尤其删除已无本机 slot，不能只依赖现有“枚举当前凭据”的 republish。此处尚未实现该耐久队列，不把离线准备当成跨设备发布成功。
- 准备结果拥有原 FilePlan，只有密文操作和必要的新 key，没有目标数据库/文件写入；选择失败或取消释放私有来源与计划，已经准备的明文和新 key 使用零化容器。公开 Debug 仅显示操作数量/是否需安装 key。目录至多 100000 项/16 MiB 名称、每个名称 4096 字节、值沿现有预检 64 MiB 上限，逐项检查取消。前后重新核验来源及目标文件版本。

定向验证以当前生产 TypeScript 生成的合成向量验证 Rust 解密，并用生产 TypeScript 解开当次 Rust 新密封的结果，覆盖 Unicode、空串、TextDecoder 的 BOM 行为、错误 slot/key/version 与篡改拒绝。真实不同设备 key/master key、明文相等/本机漫游不同、选择后重新密封、原历史事件不变、保留目标会话、离线删除、新 key 不落地、部分准备后失败与目录释放均通过。完整恢复仍需领域决定/事件时钟、耐久离线发布、原子提交和宿主选择 UI。

# 完整备份实现边界

OPS08 仍未完成。当前产品入口继续使用 `backup-io.ts` 的 v1 子集，不能把下述原生基础当作已经可用的完整备份或合并恢复。

## 已实现：私有原生快照

`storage/backup_snapshot.rs` 提供内部 `capture`，尚未注册 IPC，也不向 Agent、插件或用户交出暂存路径。调用者必须持有原生 Db 锁，并沿用 `withPluginDataBackup` 的宿主准入；捕获与目标文件计划均须显式传入由当前 AppHandle 解析的 BundledPrograms，不能默认猜测应用数据目录中的内置副本。输出对象持有带跨进程租约的私有目录；正常释放、失败和取消都会尝试回收。锁或文件系统错误阻止删除时，保留归属标记并记录日志，启动后重试。

- 捕获先确认 reading_sessions_pending 为空；未关闭时返回 backup/incomplete，不复制或丢弃无可移植身份的待结算桶。
- 在同一 SQLite 读事务中固定来源版本，使用 SQLite Backup API 按页复制所有实际表、索引和触发器。不是复制正在使用的主数据库文件，也不依赖 WAL 侧车随包移动。
- 保留事件日志、实际投影、聊天呈现状态、私有文档、本机配置和同步 bookkeeping。旧数据中日志未记录的变化也保留，不能用一次 replay 取代这份数据库。
- 清单列出所有非 SQLite 内部表的行数（包含 FTS shadow），以及独立数据库、每个登记且未删除的 blob、外装和当前解包的内置插件程序、已有 `secret.key` 的路径、字节数和 SHA-256。新增普通用户表自动进入数据库及清单。
- Blob 路径必须匹配宿主按 key 生成的受管路径。远端占位、缺失文件、坏大小或哈希不匹配均拒绝，不能默默省略并称完整。历史无哈希行会对本次复制计算哈希，不修改活库；其旧身份不能凭空恢复。
- 所有插件更新 journal 必须先结束。候选目录、更新回滚副本、日志、临时资源和可重建缓存不进入快照。普通插件存储写和领域写在原生层不能把多个数据库时点混在一起。
- 文件按 1 MiB 缓冲复制，支持块间取消；清单至多 100,000 个成员，插件遍历至多 100,000 个目录项、32 层、单份 manifest 至多 1 MiB，总捕获上限 512 GiB。超限拒绝，不截断。复制后按实际大小和登记哈希验证；准备结果另有可取消的完整性复核。
- 拒绝路径逃逸、符号链接和非普通插件文件。宿主 Db 锁阻止正常程序切换；针对另一连接的 blob 文件变化仍以登记哈希复核。不是对同一 OS 用户恶意并发改文件的隔离沙箱。
- 凭据仍以密文保存在数据库，复制已有 32 字节 key 并核实可解密。缺 key 时失败，绝不为备份创建或替换 live key。Unix 暂存目录为 0700；此处同时持有密文和解密材料，**不得作为未加密 ZIP、资源句柄或普通另存为文件交付**。

清单 format 2 是内部完整归档版本，与既有 v1 JSON 文件格式无关。它要求来源已在自己的设备上关闭全部待结算阅读桶；尚未交付用户的内部 format 1 明确拒绝，不能按时间区间猜测其阅读身份。

## 已实现：同步生产者的备份准入

`withSyncBackup` 是插件数据和阅读暂停的外层：关闭新同步工作的准入，等当前周期（含拉取后去重/漫游覆盖）、延迟书籍/封面下载、启动去重和连接/断开持久化的真实结果，再冲刷同步触发的KV与事件尾部。之后才允许备份进入插件数据屏障，避免反向阻塞正在结束的漫游覆盖。排空期间网络失败仍由同步调用方报告；已经应用的合法本地前缀可以备份，不强制联网成功。

现有v1导出/导入已接入。v1原有取书路径会按需下载缺失原文件，因此导出获得当前备份范围内的专属fetcher，下载仍使用同一引擎/加密/本地文件实现；普通下载和新周期等待释放，结束后的fetcher不可复用。范围失败或取消也须等已受理物理工作结束，不让迟到下载写进下一次操作。延后调度器任务在恢复准入时重验是否已退休。断开连接也等待凭据删除，不能删除失败却宣布本机profile已断开。

隔离宿主测试覆盖真实调度器及v1入口、插件数据锁顺序、缺失书籍下载、导入取消、事件尾部、连接延后和旧调度器退休；引擎/原生使用替身，未声称真实网络或Tauri验证。此准入不覆盖其他领域的前台/Agent/插件写者，也不是原子恢复。完整归档宿主尚须在捕获/最终决定的短暂窗口使用所有生产者屏障。

## 已实现：有租约的私有暂存与启动回收

`backup_staging.rs` 将快照、认证解密结果与事件计划的目录统一为 `BackupDirectory`。生产捕获、解密和规划接口只接受 `BackupStaging`，由原生启动根据应用数据目录创建并放入 Tauri state；不再接收任意暂存 Path。合成路径和无租约的认证输入夹具只存在于 cfg(test)。当前 AppData 下的 `backup-staging-v1` 是暂存协议目录，与归档 format 2 / 既有 v1 JSON 无关。

- 每个随机命名的目录先创建带 application_id/user_version 的独立 SQLite 租约文件，并持有 EXCLUSIVE 事务，之后才允许写入私有数据库、凭据 key 或解密字节。租约随对象所有权进入来源预检、行/文件计划，最后释放；通过已有 SQLite 的跨进程文件锁判断活跃状态，不采用 PID、心跳或过期时间猜测，也没有新增锁依赖。
- 创建、清理和租约最终退役共用 `.control/registry.sqlite` 的排他锁，避免清理器抢在创建者完成初始化之前删除目录。租约忙表示仍在使用，原样保留。注册锁忙或文件系统失败时不阻塞 UI/伪报成功，返回现有 db/locked 或记录后台日志，目录保留以便重试。
- 原生 setup 在数据库初始化前注册暂存管理器并启动后台回收，不阻塞主窗口或数据库恢复。只处理专用根下格式匹配的目录及可验证的本协议租约；陌生文件、错误标记、缺标记却有正文的目录和符号链接保留并报告。根扫描至多 10000 项；空的未初始化目录可清除。不会扫描或删除任意系统临时目录。
- **正文先删，租约最后退役。** 清理全程持有注册锁，逐项删除正文时保留租约；所有正文清空后关闭租约连接，再删标记和空目录。清理中断或文件删除失败后仍可在下一轮确认归属；在最后一步退出只会留下空目录。正常 Drop 使用相同顺序，避免 TempDir 在失败时先删租约。连接先于所属目录关闭，兼容 Windows 的打开文件约束，实际跨平台故障仍待集中验证。
- Unix 根、控制目录和暂存目录均为 0700；租约与控制文件不进入加密归档或源数据库，也不属于同步数据。捕获清单明确排除私有备份暂存。此目录只承载可丢弃的准备结果，**不得用作已作出恢复决定的 journal 或跨重启恢复文件**；后续原子恢复必须先将其所需内容交给独立耐久位置。

真实子进程持有含合成凭据的暂存目录，父进程回收确认其仍活跃；终止并等待子进程退出后再次回收成功。另验创建/清理注册锁互斥、正常释放、锁忙延后、中途删除失败后保留租约并重试、陌生/缺失标记与符号链接保留、0700 权限。真实口令归档往返中，解密→只读预检→事件计划持续保留源租约，同时计划目录有独立租约；释放计划后两者清理，快照租约不进入 manifest。相关快照、归档/预检/计划回归及原生编译通过；未提前执行集中 Tauri、实际 Windows/Linux 或无关前端检查。

## 已实现：认证加密归档编解码

`storage/backup_archive.rs` 与 `backup_archive_read.rs` 是内部编解码器，尚未注册 IPC 或接入用户密码流程。使用 [age 的口令加密流](https://docs.rs/age/latest/age/) 包裹 tar；数据库、清单、文件名、插件程序及已有凭据 key 全在加密载荷内，不产生中间明文 tar。

- 写入目标同目录的临时密文文件；逐成员核对快照大小和 SHA-256，完成 tar、age 最终认证标签并同步文件后才替换目标。取消、来源篡改或写入失败不会先截断旧备份。
- 口令使用零化的 `SecretString`，要求至少 12 个字符、至多 1024 UTF-8 字节。写入 scrypt work factor 为 18，读取拒绝更高值；age 首次构造另有机器默认值校准，不能据此声称整个进程严格限制为一次 KDF 的资源量。校准和单次 KDF 无法中途取消，前后及文件处理块间检查取消。
- 读取限制 age 头为 64 KiB、密文为 512 GiB 加 2 GiB 元数据空间；清单至多 32 MiB、100,000 成员、路径 8192 字节、声明文件合计 512 GiB。tar 原始模式仅接受普通文件和有界 GNU 长路径，拒绝链接、PAX、稀疏等其他成员类型；不信任文件权限或外部路径。
- 先验证清单与路径，逐块解密至私有临时目录；成员必须唯一、大小及 SHA-256 匹配，不允许未声明/缺失成员、大小写碰撞、父文件重叠、Windows 设备名或路径逃逸。文件用 create-new 创建，文件系统别名碰撞不能覆盖已有成员。
- tar 结束后继续读到 age 认证 EOF，拒绝截断、损坏、非零尾随数据或拼接归档。只有完整通过才返回 `AuthenticatedBackup`；失败、取消、正常释放清理暂存目录。此阶段不会打开 SQLite，也不会修改活库。**密码认证和文件哈希通过不等于数据库结构、事件身份或应用语义可信**。
- 稳定错误码区分归档结构、解锁失败和口令规则，八语言只显示本地化提示。过高 KDF 开销按 age 的类型化错误映射，不调用其可能发生整数下溢的时长文案格式化；没有修改依赖或放宽上限。

## 已实现：只读结构与来源一致性预检

`backup_preflight.rs` 接受 `AuthenticatedBackup`，返回拥有私有归档和已固定读事务的 `PreflightedBackup`。结果只供内部合并规划，不是恢复许可或最终回执。当前只接受本构建 schema 42；不在导入副本上运行迁移，也不执行它的 DDL 到活库。

- 打开前要求独立 rollback-mode SQLite 文件，拒绝需 WAL 侧车的输入。连接为只读，配置 defensive、trusted_schema=OFF、禁用触发器/视图、query_only、禁用 mmap；不注册应用函数，不启用扩展加载，附加数据库上限为零。采用 [SQLite 对不可信数据库的防护建议](https://www.sqlite.org/security.html)。
- 先做完整 integrity_check，再和现有迁移在空库生成的结构逐项比较，覆盖表、索引、触发器、FTS 与 shadow，逐条核对完整迁移记录，不将任意长度的来源记录列表收集入内存。额外对象、缺失/改写结构拒绝；不会跳过未知用户表。空的旧 blobs 表及 SQLite 自己生成的 sqlite_stat1/4 允许正常缺省，后者若存在仍比对结构。
- 逐行检查 SQLite 实际值类型、非空/主键、UTF-8 和持久 JSON，实际全表计数必须匹配清单。app_kv 仍按原契约保留插件任意字符串和密封凭据，不强迫其内容为 JSON；不重放、不要求实际投影与事件相等。
- 核对事件版本、非空身份、JS 安全整数 HLC 和对象 payload。原 schema 唯一约束加 integrity_check 保证来源内事件 ID/HLC 唯一；未知事件类型原样保留，尚不宣称其 payload 领域语义已验证。声明外键与消息→线程引用检查；可随删书继续存在的插件文档出处等不擅自改成级联关系。
- 未删除 blob 登记必须和认证成员一一匹配受管路径、大小/已有哈希；额外 blob 或缺失成员拒绝。实体书必须有原文件，ready 封面必须有登记文件；虚拟书必须有格式正确的内容绑定，不把缺失/禁用提供者冒称可读或离线可用。
- 校验已有凭据 key 可解密、插件目录身份和 manifest 的 schemaVersion、私有文档 owner 及宿主存储版本。凭据使用只读 `decrypt_existing`，正常捕获也复用它；缺失/坏 key 不会创建或修复。未结束的插件更新 journal 拒绝。程序与目标存储版本、权限及完整 manifest 由下述程序审阅接续；实际迁移仍归宿主恢复流程，预检不激活来源程序。
- SQLite 单行/值上限 64 MiB、SQL 长度 256 KiB、列数 128、表达式深度 64、结构对象 4096、结构文本合计 4 MiB；整个预检有五分钟处理期限，每 1000 条 SQLite VM 指令和 Rust 行/文件间检查取消。这里不是整个进程的严格内存上限。超限/结构问题使用已有 backup/invalid-archive，取消保留 backup/cancelled，本机文件和锁错误保留原有 fs/* / db/locked，避免误称备份损坏。成功移除该阶段计时器，读事务留给下一阶段，失败或释放关闭连接后清理目录。

定向用例保留日志未记录的历史记忆、聊天呈现 error、未知事件及已删书的插件文档出处；验证 VACUUM/ANALYZE 后正常接受。读连接写入、ATTACH、扩展加载拒绝，源数据库字节未改且无 WAL 侧车。恶意视图/触发器、额外表、缺索引、伪迁移、坏类型/JSON/HLC、坏引用/文件登记、更新未决、伪计数/密钥/插件身份、取消和 SQL 中断拒绝并清理。

## 已实现：事件匹配计划与目标数据库版本检查

`backup_event_plan.rs` 的 `plan_events` 消费预检后的来源，并在一个目标读事务中计算数据库版本和所有事件匹配。结果拥有来源及私有计划库，正常释放、失败和取消会清理；没有目标写入、重放或恢复许可。

- 分别按事件 ID 和完整 HLC 查询目标，保留 new / existing / ID conflict / clock conflict / both 五种结果。相同 ID 只有整个不可变 envelope 相同时才视为已存在；另一 ID 占用相同 HLC 不能被去重吞掉，两个键同时冲突会同时记录。
- 比较全部 envelope 字段及 payload，排除每台设备自己的 ingested_at。payload 按 JSON 值比较：忽略空格和对象键顺序，规范化 1 / 1.0 / 1e0 与正负零；不经 f64 转换归一化大整数，保留数组顺序、类型和来源字段差异。坏目标 JSON 或身份读取失败会报错，不能等同于目标不存在。未知事件仍是保留事实，匹配不证明其领域语义有效。
- 来源逐条扫描，目标按两个索引查找；私有 SQLite 计划只记录 ID、分类和摘要，不复制正文/密钥。分页至多 100 条，续页按主键 seek，不把整个日志或冲突清单堆入内存。调用者提供取消检查；SQL 行间及大字段每 1 MiB、JSON 节点间检查，单条事件 JSON 仍有 64 MiB 上限。计划不承担跨重启恢复日志的职责。
- 目标版本是带类型和长度边界的 SHA-256 摘要，覆盖 schema、所有实际表（含私有/本机/统计及 FTS shadow）与隐式 rowid。保留 BLOB/TEXT、NULL/空串等区别，不只比较行数或最新 HLC；不带 rowid 的表按主键排序。结构变更、同条数更新、私有设置、设备身份变化都会使旧计划失效，属于保守的全库检查。
- `verify_target` 必须在将持有最终数据库决定的事务内调用，优先 IMMEDIATE；检查之后不能释放事务再写。变化返回已有 backup/changed，要求重新规划。第二个真实 WAL 连接在规划期间修改事件时，计划仍使用同一旧视图，后续目标检查拒绝它。

此阶段只关闭事件身份识别及数据库预览过期检查的基础缺口。冲突尚未消解；没有事件或实际投影被导入。数据库版本不包含磁盘文件字节或运行时状态，完整流程还需文件版本、运行时排空和宿主确认。后台读取引起的持久 bookkeeping 变化也可能使计划过期，不能据此省略后续静止窗口设计。

## 已实现：实际数据差异与处理方式

`EventPlan.plan_rows` 接续原事件计划，在新的目标读事务中先验证原数据库摘要，再生成 `RowPlan`。因此两段计划针对同一逻辑目标版本；行规划期间的第二个 WAL 连接变化不会混入当前读视图，最终决定前仍会被原版本检查拒绝。

- 当前源/目标的每张实际表都有处理方式，包括事件投影、聊天、插件私有文档、旧 vocabulary_entries、普通设置、凭据、虚拟书绑定、文件登记、未结算阅读、本机状态及派生索引。新增未知表会失败，不默默遗漏。事件身份继续使用上一阶段；schema/索引/检查点/本机版本钟等明确交给校验或重建；未完成插件更新 journal 和未迁出的 inline blobs 拒绝。
- 有数据责任的普通表按真实复合主键生成带类型/长度的二进制身份，保留空串和 NUL，不用字符串分隔符拼键。源与目标逐行写入同一私有计划库，记录 source-only / target-only / same / different；没有根据缺行推断删除，也没有选择胜方。摘要反映实际 SQLite 值，JSON 字面格式变化在这里仍是存储差异，不等同于领域冲突。
- 聊天 seq、parts_json 和 error 均进入实际差异；不因它们不在日志投影中而省略。插件文档 revision 不参与内容摘要，但保留完整摘要以单独报告 generated-only；后续通过正式写入生成新的并发身份，不将旧 revision 当作应覆盖的业务字段。

## 已实现：耐久凭据发布与启动保护

Schema 42 的 `restored_credential_publications` 是仅存 slot/创建时间的本机操作记录，无凭据值，不是跨设备投影。`PreparedCredentials.enqueue_publications` 要求与最终本机凭据写入处于同一恢复事务；不会将来源队列直接克隆。凭据目录也枚举两侧队列，保留“只有待发布删除、没有 KV 或漫游行”的恢复选择。通用 RowPlan 将原队列分为保留当前设备的运行状态；重放不清除，wipe 清除。

- 原生 pending 最多返回 100 个 slot；publish 接受最多 100 个宿主新生成的 envelope，并按累计 16 MiB 明文控制密文回执体积（单个更大的合法值独立发布，余项保留给后续批次），只处理仍有记录的 ai-api-key 项，拒绝非本机身份、非 system/preference 事件与重复项。内容不信任调用方：在 Db 锁和 IMMEDIATE 事务内重读当前本机凭据与当前 master key，按既有格式密封/生成 null，沿正式 commit_events_in_transaction 追加日志、更新投影/同步 outbox，并删除待发布记录。任何一步失败全事务回滚；重复调用/丢失回执后已完成 slot 是无操作，不重发旧值。
- 缺 master key 时保留记录；用户在离线恢复后又改值或删除，发布时采用最新已保存值，不保留第二份旧明文/密文快照。准备阶段不再提前生成漫游 payload，避免留下可以误用的旧 key/旧值；在线与离线都走同一耐久发布器。
- preferences_load_all 在记录尚存时排除对应旧漫游行，避免启动或同步覆盖掉已恢复的选择。宿主在启动/刷新覆盖前、连接后 republish 前及每个同步周期拉取前尝试排空；等待已有凭据写完成，复用同一进行中的任务，只有原子提交成功后广播真实已写入事件。失败沿现有启动/同步日志和错误路径处理，记录留下重试。
- 发布先重读持久化日志/检查点 frontier，再用原有 JS HLC 分配器生成 envelope，避免引入第二个本机时钟分配器。事务发现竞争时返回 backup/changed，最多三次重新读取/分配；持续竞争保留记录并返回失败。新 IPC 不返回明文/key，不开放给 Agent/插件为任意 slot 创建记录。

## 已实现：捕获与合并规划前关闭本机阅读事实

`backup_close_reading_sessions` 是宿主内部 IPC，`closeReadingSessionsForBackup` 是严格准备函数，尚未接入完整备份入口。待结算桶仅以书籍/本地日期/小时定位，没有跨设备事件身份；因此在来源设备捕获前、目标设备合并规划前先关闭自己的桶，使用既有 `book.sessionRecorded` 事件 ID 去重，不依据重叠时间猜测已导入量。

- 宿主读取待结算目录，重读持久 frontier 后使用原有 JS HLC 分配器生成 system/book envelope；与凭据发布共用此入口。原生持有 Db 锁，在 IMMEDIATE 事务内重读实际目录、最新时间与位置，不采用调用者旧 payload。目录必须完整匹配，本机新时钟必须合法；竞争返回 backup/changed，宿主最多重读三次，持续失败直接返回。
- 正式事件追加、投影/outbox 更新与桶退役复用原有 reading_session_flush 的同事务实现；任一失败全部回滚。零时间但有位置的桶仍生成事实；仅零时间且无位置的空桶可以清除。读取至多 100000 桶，书籍/日期/位置文本累计至多 64 MiB，超限拒绝。
- 只广播原生成功回执中的实际事件。全部已关闭后的请求重试不产生第二份事实；关闭后又有新的活动时，旧 ID 不得关闭新桶。后续导出失败不撤销已经成立的阅读事件；原有事件身份确保重复追加不重复累计。
- format 2 捕获、认证后来源预检和目标事件规划分别要求待结算表为空。即使归档哈希有效，含待结算行仍拒绝；捕获前出现新的阅读活动也拒绝。旧内部 format 1 尚未用户交付，直接拒绝，不静默丢弃或猜测转换。
- **阅读队列的可释放暂停已接通。** `withReadingBackup` 先同步采样当前计时，保留队列位置并等待已受理观察实际完成，再调用原子关闭并执行调用方IO。备份期间的计时/位置、切书及旧会话退休排在保留位置之后，释放才写；采样器继续使用，不把备份耗时误作停读，也不丢弃用户的新观察。准入失败/取消/操作失败均释放；排空中的取消仍等物理工作结束，已开始的IO保留真实结果。
- 现有v1导出/导入已经通过这一边界，文件格式仍是v1子集。定向验证使用生产入口、实际阅读队列及原生IPC替身，尚非真实Tauri验收。完整归档的宿主后续必须在实际捕获/规划或最终决定的静止窗口复用它；不能跨密码/选择等用户等待长期占用，也不能把它当作其他领域/插件/原生写者的统一准入或完整恢复已完成。
- 排空期间写失败会拒绝本次备份并保留既有错误报告；过去已经报告、未落库的观察不可能由备份恢复。暂停不重试失败的观察，也不改写其身份。

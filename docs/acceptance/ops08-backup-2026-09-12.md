# OPS08 完整备份与恢复：macOS Tauri 验收

日期：2026-09-12。范围：[完整备份](../features/full-backup.md)既定数据覆盖、恢复选择与失败原子性。状态：代表性桌面成功与失败通过；[交付账本](../capabilities/host-capability-delivery.md)记录对应实现和提交。

## 环境与隔离

- 实际 Tauri debug 二进制，使用 `tauri.capability-e2e.conf.json` 与独立 identifier `com.readaware.app.ops08-e2e`；AppData 与用户正常资料库分离。
- 前端为当前工作区 Vite；原生编译包含本次恢复执行器及 data-only 禁用修复。Tauri MCP 操作 webview，Computer Use 操作 macOS 原生保存/打开面板；没有用浏览器壳代替应用。
- 编译目标在 `/tmp/readaware-ops08-tauri-target`，临时 bundle 为 `/tmp/ReadAware Backup Tests.app`。合成测试数据与凭据不接外部服务。
- 归档本地证据：`/tmp/readaware-ops08-source.age`，1484310 字节，SHA256 `f0a5c1c8d19cb6d7b297ea6c892ef1aa5fd64fe7258bc31cb83374a46ab07a3a`。原生保存面板首先保存到 Documents，再复制到该路径用于重复测试。

## 夹具与复现步骤

1. 在隔离应用中通过实际域命令导入 699 字节 FB2，书名 `OPS08 Backup Acceptance`，bookId `4682691c-d2d9-46cc-aa52-9aeb0209d097`。写入来源批注、书单、记忆、会话，以及 `ops08-proof` 插件 KV、文档与 schema1；设置合成凭据槽 `ai-api-key.ops08-proof`。插件为禁用状态。
2. 来源插件为版本1.0.0/schema1，storage服务要求`^2.0.0`，无额外权限。通过设置中的完整备份表单输入口令、重复确认，在实际原生保存面板保存 age 文件；界面显示完整加密备份保存成功。
3. 修改目标书名、记忆、插件KV/文档、合成凭据及书籍文件字节；增加 `OPS08 target-only collection`。目标插件改为版本2.0.0/schema2，真实 `migrate` 先校验私有KV和文档来自备份，再写入迁移结果，并立即读取KV确认Worker镜像已更新。
4. 使用错误口令导入归档。实际界面显示解锁失败并回到可重试表单；只读查询确认目标书名、记忆及插件值未改变。
5. 使用正确口令打开同一归档。预检显示0新事件、3条待选择记录、1文件、16插件和1凭据。点击“Select backup data”后待选归零；点击“Check choices”通过记录约束，再点击“Confirm and restore”。本轮保留当前插件代码，使用备份插件数据。
6. 第一轮成功结果为9条领域记录、1文件、16插件namespace、1凭据。通过实际SQLite、文件字节/摘要和native secret_get检查恢复结果；凭据仅比较相等性，不在证据中输出值。
7. 重载前从实际加载的 DomainWriteGate 模块调用普通写入，得到 `backup/busy`。点击“Reload restored library”，应用完成启动；打开恢复书籍，Foliate显示来源原文，侧栏显示恢复会话。
8. 第二轮把目标插件数据改为 `target-second`，将当前代码改为先 `storage.set("attempt", "private-only")` 再抛出 `OPS08 staged migration failure`。再次从UI审阅、选择备份数据并恢复。实际Worker报错返回审阅，原始原因进入日志；SQLite中目标KV/文档仍为target-second，没有attempt行。
9. 在同一审阅页展开Plugins，为ops08-proof选择 `Backup · plugins/ops08-proof`。重新检查并确认恢复，实际出现 `Install OPS08 Migration Proof?`、版本1.0.0、信任说明及权限列表。点击Install后成功恢复14条领域记录、2程序文件、16namespace和1凭据；源码/manifest恢复到来源版本1.0.0/schema1，KV与文档恢复为来源值，失败迁移的attempt仍不存在。再次点击重载正常返回书库。

## 针对性验证与边界

本轮原生5项共同apply测试覆盖真实age恢复/重放、文件安装后取消回滚、所需blob及程序同意门、新目标自己的key、data-only保留代码但禁用插件。宿主任务/挂载11项及生产apply/准备4项验证一次性决定、取消时保留物理回执、正常失败释放屏障、成功或恢复未完持续持有屏障。Web和desktop验收代码类型检查通过。

既有原生文件恢复测试以真实子进程在COMMIT前/后exit(73)，重开SQLite和文件验证旧/新状态一致；另有损坏恢复资料留存、修复后重试、取消、写锁、路径/来源变化拒绝。归档、来源预检及凭据测试补充密文尾部篡改/截断、缺key/文件、不同目标key重密封等失败证据。它们是原生定向测试，不称作实际桌面断电测试。

本次代表性验收是macOS debug Tauri。未验证Windows/Linux、物理断电、packaged CSP或已部署远端同步。Agent/maintenance插件共用用户确认流程的接线与状态回执有定向测试，本次没有真实模型请求或跨重启Actor回执测试。新导入文案为英文/简体中文，其余语言使用既有英文fallback。

# 插件资源限制与网络重试

本页合并 Worker 通信预算和网络传输预算。前者约束插件与宿主之间的消息及存活资源，
后者约束实际网络请求与正文流量；两套额度分别计数，不能拿一个代替另一个。

<a id="worker-transport"></a>
## Worker 通信与存活资源

单消息形状/字节验证之外，宿主对全部 Worker 使用同一个资源池和双向流量桶。额度不接受插件传入的 owner、计数或释放数；同 ID 更新候选与旧实例各自持有真实租约，共享总限额。

### 存活资源

| 资源 | 单实例既有上限 | 全 App 上限 |
| --- | --- | --- |
| 进入宿主的在途 RPC | 256 | 1024 |
| 等待 Worker 回调的 RPC | 256 | 1024 |
| 注册与在途注册预留 | 4096 | 16384 |
| 解码后持有的回调 | 200000 | 500000 |

每个进入宿主的调用先预留 RPC 与注册额度，之后才解析方法并执行业务。满额稳定返回 plugin/busy，不能先替换贡献再发现超限。普通结果释放预留；返回 disposable 时租约转移给真实注册，注销/退休清理释放。回调按已解码图中的唯一 handle 租约计数，单个回调释放和整实例退出均幂等，不能靠重复释放、复用 handle 或替换实例降低其他持有者的计数。

进入宿主的 RPC 等处理承诺实际结束才释放；向 Worker 的调用在结果、超时或实例终止时释放等待项。已派发持久写仍走既有生命周期排空，不因超限假装回滚。原生源读取/异步资源有各自的清理生命周期，这个表不是其内存计数。

### 消息流量

| 维度 | 每实例突发 / 每秒恢复 | 全 App 突发 / 每秒恢复 |
| --- | --- | --- |
| envelope 数 | 16384 / 4096 | 65536 / 16384 |
| 核算字节 | 256 MiB / 64 MiB | 512 MiB / 128 MiB |
| 图访问项数 | 4000000 / 1000000 | 16000000 / 4000000 |

两方向共用额度，含启动、控制、取消、结果、同步、释放和非法消息。先计 envelope 再遍历数据图；图按原单消息算法核算，失败时也结算已经访问的字节和项数，不让超大或非法请求成为免费路径。时间使用单调时钟，恢复不超过突发上限；不退还流量，实例重启不能清空全 App 的桶。

累计流量耗尽时退休触发超限的实例，取消等待、移除贡献并排空已接受工作，不继续为洪泛逐条生成拒绝回包。不能丢弃同步消息却让插件继续使用旧镜像。未触及累计限额的普通单消息错误仍沿用原有稳定拒绝与恢复语义。全 App 桶不预留每插件份额，繁忙时其他实例也可能在下一次发送/接收时触及总上限，不能宣称公平带宽保证。

这是宿主消息准入和存活句柄上限，不是 WebView/OS 队列、structured-clone 峰值内存、插件自身 CPU/堆内存或全部业务对象的硬限制。原生网络累计额度、完整业务压力与跨平台打包验收分别保留在 SYS07/CON04 中，不能由此自动关闭。

<a id="network-transfers"></a>
## 网络传输与安全重试

Network 2.2 在既有逐跳授权、流句柄、取消/排空、8/32并发和120秒绝对生命周期上增加共享累计额度与显式安全重试。没有第二个网络实现，也不开放原生代理/TLS参数、Cookie仓库或任意后台队列。

### 累计额度

插件按宿主绑定的 plugin ID 计费，同 ID 的重启/更新候选共享额度；所有 Agent 下载按单一 agent owner 计费，不按用户可新建的对话分散预算。两类请求共享宿主池。

每 owner 的60秒窗口最多120次原生请求和2 GiB正文；全 App 对应480次与8 GiB。窗口从首次使用开始，使用单调时钟；不是平滑带宽保证，跨窗口可突发。最多保留1024个未过期owner，过期才回收，不因插件停用重置债务。App进程退出后计数不保留，不是跨设备/计费额度。

每次实际派发前核算请求及上传正文，跳转和重试都再次核算；超限不派发。每块原生正文读出后、向调用者交付前核算下载，溢出块不交付，但已读字节不能退款，额度债务保留到窗口结束。失败和取消不退款。network.policy返回固定窗口/额度及重试规则，不暴露别的插件用量或凭据。

这里的字节是上传正文和已读取的解码响应正文，不包含HTTP头/TLS开销、压缩前线上流量或取消前原生内部预读；不是网卡级限速。单流/单块/Worker传输预算仍独立有效。

窗口额度耗尽使用plugin/network-rate-limited，不混同不可恢复的单消息quota错误；八语言提示一分钟后重试，Worker传输只保留稳定code也能正确呈现。它不会触发内部自动重试。

### 重试语义

插件默认不重试，fetch/openStream第三参数可明确传retry=safe。Worker在异步读取Request前复制选项，宿主复核只接受none/safe，不接受调用者自定次数/期限/授权。RSS0.14已接入，沿用原15秒调用期限；TTS和WebDAV写请求不隐式增加重试。

仅原始请求是无正文GET/HEAD时允许重试；POST经303变成GET也不会获得重试权。整个跳转链最多重试2次，只在响应头尚未交付时针对原生传输失败或429/502/503/504。其他HTTP结果照常交付，取消、超时、拒权和额度错误不自动重试。

退避500/1000毫秒；Retry-After支持秒数或日期，不早于退避，超过30秒直接交付HTTP错误而不是提前再试。错误响应先取消正文再等待；等待受原signal和绝对期限约束，停用/撤权不会等待退避结束后再发。每次尝试复核激活、目的地和额度，原来的逐跳授权、禁止HTTPS降级、跨源敏感头剥离不变。正文读取/流offset回执永不重放，已经保存的部分数据不假装可恢复。

Agent批准下载复用同一个重试器及额度，只重试原已批准HTTPS URL的GET，不跟随重定向，重定向仍需重新批准；拿到200头后才创建临时资源。没有永久离线队列、无限等待上线或断点续传，离线重试耗尽后返回真实网络错误。

### 证据

核心窗口/重试、真实宿主服务/请求owner、Agent下载编排和RSS消费者有回归；真实Bun Worker证明第三参数穿过flatten和RPC，调用者随后的选项修改不改变请求。隔离macOS debug Tauri模块Worker经原生HTTP访问自有本地夹具，503后500毫秒退避再得到retried-native，服务端恰为2次请求，探针随后退休。不是公网服务、真实模型批准下载、大文件慢网或packaged跨平台验收。
